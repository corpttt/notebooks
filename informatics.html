Доклады: смысловая часть семинар 1

Без явных требований доклады «плывут» по качеству. Те же принципы полезны для практик, ВКР и любых защит. Рекомендованная книга: Алексей Каптерев, «Мастерство презентации».

1. Тема — узкий аспект

Тема — основная идея / предмет выступления. Её нужно сузить.
  1. Какую цель я преследую, говоря на эту тему?
  2. Успею ли раскрыть за отведённое время?
  3. Понятно ли, о чём доклад, если сказать только цель?
Пример. Плохо: «Космос и его исследование» — непонятно, чего ждать.
Лучше: «Новые технологии в исследовании экзопланет: перспективы для поиска жизни» — слушатель знает сюжет до первого слайда.

2. Измеримая цель

Измеримая цель — ориентир подготовки: в конце можно проверить, достигнута ли она. Она же помогает слушателю быстро понять суть.
Пример. Плохо: «хочу рассказать о влиянии экологии на жизнь».
Лучше: «объяснить, как пять ключевых проблем экологии влияют на качество жизни» — по пяти пунктам видно, закрыл ли доклад.

На защитах измеримость часто = улучшение метрики / конкретный результат.

3–4. Структура

Структура — не только порядок, но и распределение умственной нагрузки и контроль времени. Без неё: потеря вовлечённости (сложные вещи «на лету»), сжатость в конце (время ушло на первые слайды), слабые выводы.

Точность, объективность, логичность. Без эмоциональных заявлений «от себя». Факты — из статей, книг, исследований, собственных вычислений; указывай источник.

Доклады: визуал и подача

1. Один слайд — одна мысль

Не пихай всё выступление в 3 слайда. Лучше больше слайдов, чем каша. Перегруз текстом → аудитория «отключается».

2. Тезисы, не простыня

Слишком много текста заставляет одновременно читать и слушать. Крупные тезисы + картинки/графики. Метрики часто понятнее абзаца.

3. Цвета

≤ 2–3 контрастных цвета. Кислотные градиенты утомляют на длинной презентации. Нейтральный фон + один акцент.

4. Мокапы

Для интерфейсов / продуктов — полезны. Сопровождай устным описанием. Без мелочёвки (иначе все смотрят пиксели). Если можно — интерактивный мокап.

5. Рассказ, а не чтение

Цифры с семинара (группа 23Б16‑мм). Кто рассказывал — в среднем ≈ 8.7/10. Кто читал со слайдов — ≈ 2.6/10. Рассказ даёт контакт с залом и возможность поправить подачу, если кто‑то «выпал».
Резюме визуала: одна мысль · мало текста · спокойные цвета · мокап по делу · говорить, не читать.

Пример разбора доклада: паттерн «Строитель»

На семинаре разбирали студенческую презентацию прошлых лет — как образец структуры.

Строитель (Builder) — порождающий паттерн: сложный объект собирают пошагово, не засоряя конструктор десятками параметров.

Проблема. Сложный объект → либо «монструозный» конструктор, либо лес подклассов.

Идея. Разбить конструирование на шаги (методы строителя) и вызывать только нужные.

Директор (опционально). Класс, который задаёт порядок шагов; строитель их выполняет.

Исходы, события, вероятность лекция 1

Исход — конкретный элементарный результат эксперимента.
Событие — подмножество всех возможных исходов. Событие произошло, если исход ∈ этому множеству.
Кубик. «Выпало 4» — исход (и событие из одного исхода). «Выпало чётное» — событие {2,4,6}.
Вероятность (равновероятные исходы). P(A) = |A| / |Ω|. Всегда 0 ≤ P(A) ≤ 1. Достоверное событие: P = 1. Невозможное (∅): P = 0.

Своими словами. Пока все исходы «одинаково правдоподобны», вероятность — просто доля точек. Если неравновероятны — классическая школьная формула «число благоприятных / число всех» уже врёт.

Аксиоматика (для кругозора). Если исходов континуум (температура с высокой точностью), пересчитать нельзя: вводят σ‑алгебру и меру (на [0,1] — длина / мера Лебега). В базовом курсе информатики работают с конечными Ω.

Несовместные события: никакие два не могут произойти разом (пересечение пусто). Полная группа — набор несовместных, чьё объединение = всё Ω.
Совместные — обязательно имеют общие исходы. Пара событий либо совместна, либо нет — не «и то, и другое».
ПравилоФормула
противоположноеP(A) = 1 − P(¬A)
несовместныеP(A ∪ B) = P(A) + P(B)
совместныеP(A ∪ B) = P(A) + P(B) − P(A ∩ B)
включения‑исключения (3)P(A∪B∪C) = P(A)+P(B)+P(C) − P(A∩B) − P(A∩C) − P(B∩C) + P(A∩B∩C)

Сколько информации: Хартли и Шеннон

Эксперимент: три броска правильной монеты → 8 исходов; каждый можно записать битовой строкой. Источник сообщает исход — сколько в нём «информации»?

Формула Хартли. Для N равновероятных исходов H = log₂ N (бит). Логарифм — степень, в которую возводят основание, чтобы получить N.
Библиотека. 4 стеллажа × 8 полок = 32 места. Сообщение «стеллаж 1, полка 5» при равновероятности: log₂ 32 = 5 бит.

Когда Хартли «врёт интуиции». Ищешь пункт выдачи. Фраза «рядом с метро»: в Омске (одна станция) сильно сужает поиск; в центре Москвы — почти нет. Одинаковая «длина адреса» как битовой строки ≠ одинаковая полезность информации в контексте.

Своими словами. Редкое сообщение удивляет сильнее частого. Предсказуемый источник: частые исходы несут мало бит, редкие — много.

Частная информация исхода i: Hᵢ = −log₂ pᵢ.
Энтропия Шеннона: H(A) = − Σᵢ pᵢ log₂ pᵢ — среднее число бит на исход (мера неопределённости источника).
Цвет машины. p = (½, ¼, ⅛, ⅛) для чёрный / серый / зелёный / синий.
H = ½·1 + ¼·2 + ⅛·3 + ⅛·3 = 7/4 = 1.75 бит.
Если бы все 4 цвета равновероятны: H = log₂ 4 = 2 бита — максимум энтропии при фиксированном числе исходов.
Минимум — достоверный эксперимент (один исход): H = 0.
Частые исходы — короткие коды; редкие — длинные.

Неравномерное кодирование, условие Фано, Хаффман

Равномерный код 00/01/10/11 всегда даёт среднюю длину 2 — даже когда энтропия 1.75. Хочется: «больше информации → больше бит».

Неравномерное кодирование — кодовые слова разной длины.
Условие Фано (префиксный код): никакое слово не является началом (префиксом) другого. Тогда поток бит однозначно режется без разделителей.
Код под цвета. чёрный → 0, серый → 10, зелёный → 110, синий → 111.
Средняя длина = ½·1 + ¼·2 + ⅛·3 + ⅛·3 = 1.75 — совпало с энтропией.

Своими словами. Как телефонные номера: если есть 01, нельзя иметь 011 — непонятно, где конец.

замечание с лекции Классический Хаффман не всегда даёт глобальный минимум бит на сообщение (почему — вопрос на подумать / к докладу о сжатии).

Дерево префиксного кода: путь = биты.

Практический пример: избыточность языка

Буквы английского алфавита + частоты → можно оценить энтропию «источника, который выдаёт буквы». С учётом триграмм (the, ing, and), правил орфографии и контекста энтропию считают как предел по блокам; в источнике (Смарт, «Криптография») ориентир: ≲ 1.5 бит на символ.

Парадокс хранения. Буква в ASCII ≈ 5 бит в памяти компьютера, но несёт ≲ 1.5 бит информации. Язык избыточен: можно выкинуть часть букв и всё ещё понять смысл фразы.

Своими словами. Сжатие и криптоанализ опираются на эту избыточность: частоты и контекст — не шум, а структура.

Хранение чисел: прямой, обратный, дополнительный код

Бит (binary digit) — минимальная единица; «лампочка» вкл/выкл. Любые данные в машине — слова в алфавите {0,1}. АЛУ не переводит «на лету» в десятичную — работает с двоичными (иногда 16‑ричными) словами.

Без знака. k бит → 2ᵏ различных чисел. Арифметика — как учили для двоичных.
Со знаком. Старший бит — знак. Плюсы во всех трёх кодах пишутся одинаково; минусы — по‑разному.

Проблема. Неформальные определения используют нематематические слова, двусмысленны и не годятся для теорем. Плюс существуют алгоритмы вне интуиции (например, недетерминированные). Нужны формализации: МТ, нормальные алгоритмы Маркова.

Машина Тьюринга

Конструкция. Бесконечная в обе стороны лента символов · управляющее устройство (головка) · конечный набор состояний · таблица переходов.

Правило: (состояние, символ под головкой) → (новое состояние, новый символ, сдвиг L / R / N).

Идея примера со лекции: сложение двух натуральных > 0 в единичной записи. План: стереть первую единицу; идти вправо до разделителя и заменить его на единицу; вернуться влево; сдвинуться и остановиться. На слайдах есть полный набор переходов и протокол по шагам — имеет смысл один раз прогнать руками на коротких словах.

Любой алгоритм МТ можно нарисовать блок‑схемой из последовательности, ветвления и цикла (структурное программирование). Но сама блок‑схема не отвечает на вопрос «что считать алгоритмом» — это лишь картинка.

Лента + состояние. Один шаг = одно правило.

Нормальные алгоритмы Маркова

Список подстановок «подстрока → подстрока». На каждом шаге применяют первое подходящее правило. Входное слово постепенно превращается в выходное.
Идея примера: перевод из двоичной записи в единичную набором правил (на слайдах — пошаговый протокол: правило 2, снова 2, потом серия правил 1, финиш правилом 3).

Своими словами. МТ «ходит головкой», Марков «переписывает строку». Разный механизм — один класс вычислимых функций (см. тезис).

Тезис Тьюринга–Чёрча

Класс функций, вычислимых на МТ, нормальными алгоритмами Маркова и «интуитивными алгоритмами» — один и тот же. МТ может моделировать Маркова и наоборот.

Формально доказать нельзя: в формулировке участвует неформальное «интуитивное» понятие. Поэтому тезис — краеугольный камень, а не теорема с доказательством. Алгоритм удобно думать как функцию «слово → слово».

Асимптотический анализ: что считаем за шаг

Сравниваем алгоритмы по времени и памяти как функциям размера входа (универсальность: алгоритм должен работать на многих входах). Поточечно сравнивать функции неудобно → асимптотика «на бесконечности».

Ловушка «арифметических операций». Считать 2^(2^k) возведением в квадрат: для больших k «арифметических» шагов мало (≈ 10), но запись результата — сотни символов. Работа с числом длины 307 ≠ работа с числом длины 2. Поэтому для больших чисел вводят макроцифры (блоки разрядов). В курсе дальше часто ограничиваются «маленькими» числами, где арифметика — один шаг.
O‑большое. f = O(g), если ∃ N, C > 0: для всех n ≥ N выполняется |f(n)| ≤ C·|g(n)|. Запись «f = O(g)» лучше читать как «f принадлежит классу O(g)» — поэтому «O(g) = f» бессмысленно.
3n² + 10n = O(n²) (и даже Θ(n²)). Классы: полиномиальные, экспонента 2ⁿ (полный перебор битовых строк), факториал ещё хуже (Стирлинг).

Самопроверка со слайдов: доступ к 3‑му элементу массива — O(1); сумма элементов — O(n). Правда ли n² = O(n³)? Да. n³ = O(n²)? Нет. log₂ n = Θ(log₁₀ n)? Да (смена основания — константа).

Пример оценки: сортировка слиянием

Вход: массив длины n. Идея: режем пополам, сортируем половины, сливаем.

  • Число стадий слияния ≈ log₂ n (группы уменьшаются примерно вдвое, пока не останется одна).
  • На каждой стадии суммарно O(n) работы (слияние групп).
  • Итого время Θ(n log n) и в среднем, и в худшем случае.
  • Память: нужен доп. массив на слияние → Θ(n).
  • Слияние можно сделать устойчивым: при равных ключах сначала берём элемент из левой половины.

Как смотреть. Сначала рекурсия дробит массив до отрезков из одного элемента (они уже «отсортированы»). Потом пары отрезков сливаются: зелёная левая и бежевая правая половины, тёмные — уже слитые. На каждом шаге сравниваются только две «головы» половин — поэтому слияние отрезка длины m стоит O(m).

Своими словами. Это же рекуррентность T(n) = 2 T(n/2) + Θ(n) — позже на алгоритмах её закроют мастер‑теоремой.

Быстрая сортировка (quicksort) семинар 2

Опорный элемент (pivot). Выбранный элемент массива, с которым сравнивают остальные. После фазы разбиения слева оказываются элементы «не больше» опорного, справа — «не меньше». Дальше рекурсивно сортируют обе части.

Своими словами. Опорный нужен не «чтобы найти середину индекса», а чтобы разделить элементы на группы относительно выбранного значения. Середина массива — лишь один из способов где взять опорный, не сама цель.

Пример. Массив [7, 2, 9, 4, 5], опорный 5. После разбиения идея порядка: числа < 5 слева (2, 4), 5 на месте, числа > 5 справа (7, 9). Дальше сортируем [2, 4] и [7, 9] отдельно.
Среднее и худшее время. В среднем при «удачном» разбиении примерно пополам — O(n log n). Если на каждом шаге в одной части остаётся почти весь массив (опорный почти минимум или почти максимум), глубина рекурсии ≈ n, на уровне — просмотр порядка n элементов → O(n²).
Когда бывает O(n²). Уже отсортированный массив и всегда берём первый (или последний) элемент как опорный: одна часть пустая, другая — n−1. «Все элементы различны» само по себе худший случай не создаёт. «Делится примерно пополам» — как раз хороший случай, не квадратичный.

Как смотреть. Красный — опорный, оранжевый — элемент, который сейчас сравниваем, зелёные — уже попавшие в левую группу «меньше опорного». После прохода опорный встаёт между группами (тёмный — на своём окончательном месте). Нажми «Уже отсортированный»: опорный каждый раз оказывается максимумом, правая часть пустая, и счётчик сравнений дорастает до n(n−1)/2 = 36 при n = 9 — это и есть O(n²). На случайном массиве сравнений заметно меньше, порядка n·log₂ n.

Индексы, устойчивость и почему «среднее O(n log n)» мало

Сортировка индексов вместо больших записей. Если запись тяжелая (много полей), удобно сортировать массив индексов 0…n−1, сравнивая записи по ключу через индекс. Пока идёт сортировка индексов, сами записи в памяти не переставляют; перестановки касаются маленьких целых. В конце при желании один раз расставляют записи по отсортированным индексам.
Что меняется. Верно: записи не нужно двигать на каждом обмене; обмены индексов дешевле обменов больших структур. Неверно: «mergesort больше не нужен вспомогательный массив» (для слияния индексов доп. массив всё равно часто нужен) и «quicksort сам становится устойчивым» (стандартный quicksort по-прежнему неустойчив).
Устойчивая сортировка. Если два элемента равны по ключу, их относительный порядок как во входе сохраняется.
Пример из формы. Было: Анна — 4, Борис — 5, Вера — 4. Устойчивая сортировка по оценке по возрастанию: сначала обе четвёрки в исходном порядке (Анна, потом Вера), затем Борис — 5 → Анна — 4, Вера — 4, Борис — 5. Неустойчивый алгоритм мог бы поставить Веру перед Анной.

Что видно на анимации. Слияние при равных оценках берёт элемент из левой половины → Анна остаётся перед Верой. Быстрая сортировка берёт опорным Веру (4) и обменом ставит её в начало, «перепрыгнув» через Анну → итог Вера, Анна, Борис. Это ровно неверный вариант из формы семинара.

Почему одной средней сложности O(n log n) недостаточно для выбора алгоритма.
  • Худший случай разный: mergesort — Θ(n log n), классический quicksort — до O(n²).
  • Доп. память разная: mergesort обычно Θ(n), in-place quicksort — мало стека рекурсии.
  • Устойчивость: mergesort легко сделать устойчивым; обычный quicksort — нет.

Своими словами. «Одинаковое O» не значит «одинаковое время в секундах»: константы, кэш, устойчивость и память тоже решают.

Классы P и NP

P — задачи с полиномиальным алгоритмом на обычной (детерминированной) МТ.
NP — от nondeterministic polynomial, не «non‑polynomial». Недетерминированная МТ «размножает ленты» / угадывает кандидата и проверяет за полином.

На обычной МТ полный перебор часто экспоненциален (например 2ⁿ). На недетерминированной генерация вариантов «параллельно» считается полиномиальной — отсюда название.

Задача о разбиении (идея). Разбить множество на две части с равными суммами. Кодируем разбиение битовой строкой длины |A|; перебор 2^{|A|}; проверка одного разбиения — O(|A|). Типичный представитель «переборных» задач из NP.

P = NP? Открытый вопрос. Ожидаемая картина: P ⊂ NP строго. Если совпадут — мир алгоритмов сильно изменится.

Не‑пример интуиции. «NP = задачи без быстрого алгоритма» — неточно. NP — про быструю проверку. Есть задачи ещё тяжелее NP.

Вентили, сумматор, такт и триггер

Транзистор — кран, вентиль — несколько кранов

Транзистор — электронный переключатель. Ток на входе (базе) «открывает» основной поток от коллектора к эмиттеру; нет сигнала — поток закрыт. Электронная лампа работает по схожему принципу.

Своими словами. Как кран на трубе: подали сигнал — кран открыт (1), сняли — закрыт (0). Если поставить два крана подряд, вода пройдёт, только когда открыты оба — это И (AND). Если поставить их рядом (две трубы в одну), хватит любого — это ИЛИ (OR). На слайде 13 — именно такие две схемы из транзисторов.

Как смотреть. Нажимай A и B. Оранжевый провод — по нему идёт ток (1). Лампа горит — на выходе 1. Слева лампа загорается только при A = B = 1, справа — если хотя бы один ключ замкнут.

Логические вентили

Логический вентиль — схема из нескольких транзисторов, которая реализует одну логическую операцию над битами. Основных вентилей семь: NOT, AND, OR, NAND, NOR, XOR, XNOR. У NOT один вход, у остальных — два входа и один выход. На вентилях построена вся булева логика компьютера, в том числе АЛУ.

Одноразрядный сумматор

Одноразрядный сумматор (полусумматор) складывает два бита A и B и выдаёт двухразрядный ответ: младший бит — сумма S, старший — перенос C.
S = A ⊕ B (XOR), C = A ∧ B (AND).
Пример (таблица со слайда 14). 0+0 = 00, 0+1 = 01, 1+0 = 01, 1+1 = 10. Последняя строка: 1 + 1 = 2 = 10₂ → S = 0 (XOR одинаковых даёт 0), C = 1 (AND двух единиц).

Полный одноразрядный сумматор

Полный сумматор складывает три бита: A, B и входной перенос Cin из предыдущего разряда. Выход — сумма S и перенос Cout.
Формула
S = A ⊕ B ⊕ Cin, Cout = (A ∧ B) ∨ (Cin ∧ (A ⊕ B))

Своими словами. S = 1, когда единиц среди трёх входов нечётное число (1 или 3). Cout = 1, когда единиц хотя бы две: либо обе единицы в A и B (верхний AND), либо одна из A, B плюс перенос (нижний AND). Схема со слайда 15: два XOR, два AND, один OR.

Пример. A = 1, B = 0, Cin = 1: 1 + 0 + 1 = 2 = 10₂ → S = 0, Cout = 1. A = B = Cin = 1: 3 = 11₂ → S = 1, Cout = 1.

Многоразрядный сумматор

Многоразрядный сумматор — цепочка полных сумматоров: разряд i складывает Ai, Bi и перенос из разряда i − 1, а его перенос Cout идёт на вход следующего разряда. Из таких сумматоров состоит АЛУ.

Как смотреть. Сложение идёт справа налево, как столбиком в школе. Разряд не может закончить, пока не пришёл перенос справа — поэтому такой сумматор медленный: время растёт с числом разрядов. Нажми «15 + 1»: перенос «бежит» через все четыре разряда. дополнено Параллельная оптимизация (сумматор с ускоренным переносом) вычисляет переносы заранее по A и B, не дожидаясь цепочки.

Тактовая частота

Тактовый генератор — «внутренние часы» машины: выдаёт периодический сигнал, по которому синхронизируются все устройства. Любая физическая схема срабатывает не мгновенно, а с задержкой; длину такта выбирают так, чтобы за него сигналы в схеме успели установиться.
Тактовый сигнал. При 4 ГГц — 4 млрд тактов в секунду, один такт ≈ 0,25 нс.

Своими словами. Такт — это общий метроном: все вентили и триггеры меняют состояние согласованно, по одному удару. Современные процессоры — 3–5 млрд тактов в секунду, частоту меряют в ГГц. По числу тактов на операцию устройства делят на быстрые и медленные.

Не‑пример (для формы). Такт не «ускоряет вентили», не «уменьшает число вентилей» и не «укорачивает слова инструкций». Его роль — синхронизация: согласованное изменение состояний.

Триггер: как схема запоминает бит

Комбинационная логика (вентили, сумматоры) — сигнал течёт только «вперёд»: поменяли вход — выход сразу поменялся, ничего не хранится. Чтобы запомнить бит, в схему добавляют цикл: выход Q подают обратно на вход.
RS‑триггер — схема с обратной связью, хранящая один бит. S (set) записывает 1, R (reset) записывает 0, при R = S = 0 схема хранит последнее записанное значение Q₋₁. Схема со слайда 19: Q = (S ∨ Q₋₁) ∧ ¬R.

Как смотреть. Включи S → Q = 1. Выключи S → Q остаётся 1: единица «крутится» по петле обратной связи через OR. Это и есть память. Включи R → Q = 0, выключи R → Q остаётся 0. Внизу — диаграмма: как менялись S, R и Q.

Своими словами. Вентиль считает «сейчас»; триггер помнит «до следующего приказа». На практике RS‑триггер собирают из двух вентилей ИЛИ‑НЕ, замкнутых крест‑накрест (слайд 20), но принцип тот же — цикл. На триггерах построена почти вся быстрая память ЭВМ (регистры, кэш).

Не‑пример (для формы). Роль триггера — хранение одного бита. Не «синхронизация сигналов» (это делает такт), не «асинхронное выполнение задач», не «управление потоком данных между устройствами» (это шина).

Архитектура фон Неймана

Состав. Управляющий модуль (Control Unit) достаёт из памяти (Memory Unit) команды и данные, передаёт в АЛУ (ALU), результат возвращает; плюс устройства ввода/вывода (I/O). Все четыре класса элементов присутствуют — это и есть классическая схема.
Схема архитектуры фон Неймана (по слайду 23): CU + ALU = процессор; память; ввод и вывод.

Своими словами. Процессор сам по себе ничего не «знает»: CU по очереди достаёт из памяти команду, разбирает её, при необходимости достаёт данные, отдаёт АЛУ посчитать и складывает результат обратно. Анимация ниже показывает этот цикл на программе из четырёх команд.

Как смотреть. Слева память: ячейки 0–3 — команды, 7–9 — данные, и по виду их не отличить. Посередине — одна шина: по ней по очереди едут адреса, команды и числа (оранжевая «капсула»). Справа процессор: PC — номер следующей команды, IR — текущая команда, ACC — аккумулятор АЛУ. Счётчик пересылок в конце покажет, сколько раз процессор ждал шину.

Гарвардская архитектура — раздельные памяти (и обычно шины) для инструкций и для данных. На лекции: у фон Неймана команды и данные в одном месте, у Гарварда — нет. Название — от Harvard Mark I, где программа шла с перфоленты отдельно от данных.

Поэтому массовые ПК пошли по пути фон Неймана; «чистый» Гарвард остался в нишах (МК, DSP). Современные CPU часто гибрид: снаружи одна RAM, внутри раздельные кэши команд/данных.

«Узкое место» фон Неймана. Команды и данные делят одну шину между процессором и памятью → ограничена пропускная способность канала. Процессор часто ждёт память. Это не «нельзя менять программу» и не про float.

Процессор, память, шина, прерывания

Процессор по очереди выполняет команды из памяти. Число ядер ≈ число независимых управляющих устройств: ядер может быть одно или несколько — фразы «всегда одно» / «всегда несколько» ложны. Разрядность связана с числом бит, которые процессор обрабатывает за такт (и/или использует для адресации).
  • Регистры — крошечная сверхбыстрая память «прямо сейчас».
  • Кэш — быстрее оперативной памяти (RAM), но обычно меньше; буферизует частые данные.
Верные утверждения для формы. Процессор выполняет команды, хранящиеся в памяти · разрядность связана с битами за такт · кэш быстрее ОЗУ. Неверные: «всегда одно ядро» / «всегда несколько ядер».
Память — система устройств для хранения данных и инструкций. Уровни отличаются объёмом и скоростью доступа; по доступу память бывает последовательной (старые ленты: чтобы дойти до ячейки, промотай всё до неё) и с произвольным доступом (RAM: к любой ячейке одинаково быстро); бывает энергозависимой (стирается без питания: регистры, кэш, RAM) и энергонезависимой (SSD, HDD, неизменяемая ROM).
Иерархия памяти (по слайду 26): чем ближе к процессору, тем быстрее и меньше.
Пример. Программа обращается к одному и тому же массиву в цикле. Первый раз данные едут из RAM (долго), потом копия лежит в кэше, и следующие обращения в разы быстрее. Поэтому для формы: «кэш‑память процессора быстрее оперативной» — верно.
Шина — способ соединения, связывающий все устройства машины. Устройства по умолчанию не знают друг о друге и общаются только через этого посредника. Шина общая, поэтому её могут захотеть одновременно несколько устройств; конфликты разрешает арбитраж (например, по приоритетам). Для быстрых устройств обычно есть отдельная шина быстрого доступа.
Устройства общаются только через общую шину (по слайду 27): адрес выставляет процессор, данные и управление ходят в обе стороны.
Прерывание — способ переключить процессор на реакцию на событие или сигнал от внешнего или внутреннего устройства. Процессор сохраняет текущее состояние работы (регистры, номер следующей команды) и передаёт управление обработчику прерываний; потом восстанавливает состояние и продолжает.
Ход аппаратного прерывания: программа «замораживается», обработчик отрабатывает событие, программа продолжает.

Многопоточность и асинхронность

Многопоточность — способность процессора вести несколько «заданий». Помогает умнее использовать уже имеющиеся ресурсы и ускорять работу. Несколько ядер для этого не обязательны (можно переключать потоки на одном ядре). Кэш не является необходимым условием многопоточности.

Закон Мура (эмпирически: число транзисторов на кристалле ~ удваивается раз в ~2 года) упирается в физику миниатюризации. Многопоточность и софт‑оптимизации — способ компенсировать «замедление роста частоты/плотности»: не поднимая магически ГГц, а лучше загружая то, что уже есть. Многопоточность сама по себе не увеличивает кэш и не уменьшает набор инструкций.

Процесс — программа в выполнении (код, данные, своё адресное пространство). Поток — легковесная единица внутри процесса: общая память процесса, свои регистры/стек. Переключить потоки дешевле, чем процессы; для переключения используют прерывания.
Процессы изолированы друг от друга; потоки внутри процесса делят общую память, но у каждого свои регистры и стек (по слайду 32).
Пример. Браузер: каждая вкладка — часто отдельный процесс (упала одна — другие живы, память изолирована). Внутри вкладки разные потоки: один рисует страницу, другой качает картинки — им удобно делить общие данные страницы. Переключиться между потоками дешевле: не нужно менять адресное пространство.
Синхронно vs асинхронно — это про организацию выполнения задач в программе. Синхронно: задачи идут одна за другой, каждая должна завершиться, прежде чем начнётся следующая. Асинхронно: задачу можно запустить и не ждать её завершения — основной поток продолжает другие дела, а результат обработает, когда тот придёт. Одновременный старт всех задач для этого не требуется.
Тёмное — клиент занят работой. Синхронный клиент простаивает, пока сервер отвечает; асинхронный в это время делает другое (по слайду 33).
Параллельно vs последовательно — это про то, как задачи выполняются относительно друг друга. Последовательно — одна после другой. Параллельно — реально одновременно, а значит, всегда на нескольких исполнителях (потоках/ядрах). Асинхронность ≠ параллельность: асинхронные задачи могут жить в одном потоке (event loop), просто основной поток не блокируется на ожидании.

Как смотреть. Четыре задачи длиной 20, 7, 10 и 8 секунд (как на слайде 34). Переключай режимы и жми «▶». Тёмная полоса — поток реально работает, штриховка — ждёт ответа извне (сервер, диск). Сравни итоговое время и строку «наш поток»: асинхронный режим даёт те же 20 с, что параллельный, но одним потоком — потому что большую часть времени задачи ждали, а не считали. Последний режим показывает, что для чистых вычислений асинхронность не ускоряет.

Не‑примеры. «Асинхронность только на многоядерных» — нет. «Асинхронные операции всегда быстрее» — нет (меняется организация ожидания, не обязательно скорость одной операции). «Для многопоточности обязательно много ядер / только при наличии кэша» — нет.

На слайдах также: аппаратный async через std::thread + мьютекс; программный — Event Loop в Node.js. Для теста по лекции №3 достаточно определений выше.

Трансляция и машинный код лекция 4

Машинный код — низкоуровневый двоичный код из инструкций, которые выполняет процессор. Это единственный код, который процессор умеет исполнять напрямую.

Своими словами. Человек пишет на Python / C++ / Java. Процессор понимает только нули и единицы своей архитектуры. Между ними нужен переводчик.

Пример. Сложение в x86: ADD EAX, EBX (результат в EAX). В ARM: ADD R0, R1, R2 (результат в R0). Одинаковая идея, разные «диалекты» ассемблера — потому что разные архитектуры.
Трансляция кода — преобразование кода более высокого уровня в код более низкого уровня. Трансляторы не только переводят, но и часто оптимизируют программу. Компиляторы и интерпретаторы — оба виды трансляторов.

Компиляция и интерпретация

Компилятор преобразует весь код программы сразу. На выходе — исполняемый файл (машинный код), который можно запускать без исходников и без компилятора.
Интерпретатор выполняет код построчно (или по частям). Отдельный исполняемый файл обычно не создаётся: для запуска нужен сам интерпретатор.

Своими словами. Компилятор — «переведи книгу целиком, потом читай готовый перевод». Интерпретатор — «переводчик сидит рядом и переводит фразу за фразой прямо во время разговора».

На слайдах также: JIT (часто исполняемые куски компилируются «на лету») — интерпретатор тоже умеет оптимизировать, но полный обзор кода даёт компилятору больше пространства.

Этапы трансляции кода

Лексический анализ — токенизация входного потока: исходный текст режется на лексемы (токены): числа, имена, ключевые слова, знаки операций.

Своими словами. Лексер не «проверяет правильность программы целиком» — он только нарезает текст на слова. Проверка структуры — следующий этап.

Пример. Строка x = 2 + 3; → токены: x, =, 2, +, 3, ;. Неверно для формы: «проверяет синтаксическую корректность» / «генерирует машинный код» / «оптимизирует» — это другие этапы.
Синтаксический анализ по потоку лексем строит дерево AST и проверяет правила языка (скобки, порядок конструкций).
Семантический анализ проверяет типы, области видимости и смысл: «можно ли сложить эти два значения», «объявлена ли переменная».
Оптимизация промежуточного представления: удаление мёртвого кода, свёртка констант и др. Затем кодогенерация — машинный код.

Схема со слайда 8: фиолетовое — анализ, зелёное — синтез / оптимизация.

Как смотреть. Жми «Шаг →»: на каждом этапе меняется представление программы. Для формы важно: лексер = токены, не машинный код и не «полная проверка синтаксиса».

Парадигмы программирования

Парадигма — подход / стиль решения задач: как устроена и организована программа. Парадигмы — про логику мышления о коде. Виды трансляции — про технический способ превратить код в исполнение.
Императивная парадигма описывает как сделать (шаги процесса). Декларативная — что должно получиться (цель / результат).

Своими словами. Императив: «открой кран, налей воду, поставь чайник…». Декларатив: «хочу чай» — детали спрятаны. Но «под капотом» декларативного языка всё равно крутятся низкоуровневые императивные инструкции — это иллюзия удобного интерфейса, а не магия.

Пример со слайда. SQL: SELECT * FROM table WHERE age > 30 — декларативно (что выбрать). Императивно пришлось бы: читать строки по одной, проверять age, копить результат…

Две большие ветки и типичные подгруппы (слайд 15).

Не‑пример для формы. Утверждение «императивная описывает результат, а декларативная — процесс» — перевёрнуто, это неверно. Верно: императивная = процесс (как), декларативная = результат (что).

Структурная (процедурная) парадигма

Структурное программирование опирается на базовые управляющие конструкции: последовательность, ветвление и циклы — вместо хаотичных переходов goto. Ключевые идеи: декомпозиция и переиспользование через подпрограммы.

Своими словами. Дейкстра («Go To Statement Considered Harmful»): goto позволяет прыгать куда угодно, и программа превращается в «спагетти». Структурный стиль: только понятные блоки if / while / for и вызовы функций.

Для формы. Верное утверждение: основной принцип — использование ветвлений и циклов вместо операторов перехода вроде goto. Неверно: «основано на объектах» (это ООП), «функции полностью изолированы» (идеализация), «всегда требует многопоточности».
Функция — подпрограмма, которая может возвращать результат. Процедура — подпрограмма, которая функцией не является (обычно «сделай действие» без возврата значения в смысле функции).

Схема со слайда 20: вход → функция → выход.

Декомпозиция: сверху вниз (от общего к деталям) или снизу вверх (от простых функций к сложным). Переиспользование: одну подпрограмму вызывают в разных местах.

Объектно-ориентированная парадигма

Класс — пользовательский тип / «чертёж»: свойства и методы. Объект — конкретный экземпляр класса, созданный по этому чертежу.

Своими словами. Класс «Студент» описывает, что у студента есть имя и метод сдать_тест(). Объект — конкретный Ярослав из группы 26.Б83‑мм.

Не‑пример. «Объект — шаблон, класс — экземпляр» — перепутано. «Класс и объект — одно и то же» — тоже нет.

Инкапсуляция

Инкапсуляция — объединение данных и методов работы с ними в одном месте (классе / объекте) и сокрытие деталей реализации: наружу виден интерфейс («чёрный ящик»).
Пример. Поле balance спрятано; снаружи только deposit / withdraw. Setter может запретить отрицательный баланс. Для формы: идея — «данные и методы в одном месте — классе», а не «класс открыт без ограничений» и не «дочерний = родитель» (это ближе к LSP / наследованию).

Наследование и множественное наследование

Наследование — класс‑потомок перенимает свойства и методы родителя: переиспользование кода и иерархия типов.
Множественное наследование — у класса больше одного суперкласса. Проблема: конфликт имён (один и тот же метод / поле приходит из разных родителей; «ромбовидное» наследование).

Ромб со слайда 28: D наследует B и C, оба тянут A — откуда брать одноимённый метод?

Своими словами. В C++ программист часто обязан явно сказать, какой родительский член брать. Python строит порядок поиска методов (C3‑линеаризация / MRO). Для формы достаточно: множественное наследование создаёт конфликт имён. Не обязательно «нарушает инкапсуляцию» или «мешает полиморфизму».

Интерфейс и абстрактный класс

Интерфейс объявляет набор методов (контракт), которые класс обязан реализовать, но не даёт их реализаций.
Абстрактный класс может содержать и абстрактные методы (без тела), и уже реализованные методы / свойства; часто хранит общее состояние для наследников.
Для формы. Отличие: абстрактный класс может включать реализованные методы и свойства; интерфейс — только абстрактные методы для реализации. «Это одно и то же» — неверно.

Полиморфизм

Полиморфизм позволяет работать с разными классами через общий интерфейс: один и тот же вызов метода — разное поведение у разных объектов.
Пример. У Dog и Cat метод speak(): вызываем одинаково, слышим разное. На слайдах 42–44: команды «Свет»/«Тьма» принимают разных Hero через абстрактный базовый класс — иначе при статической типизации пришлось бы миллионы конструкторов под комбинации. Для формы: полиморфизм улучшает гибкость и расширяемость; это не «только для статической типизации» и не «в ООП нежелателен».

Декларативные парадигмы: логика и функции

Логическое программирование (Пролог): описываем факты и правила, а не пошаговый алгоритм. Программа как экспертная система: задаёшь вопрос — движок ищет доказательство (обратный вывод, возврат при неудаче).
Пример. parent(john, mary). и правило child(X,Y) :- parent(Y,X). Вопрос ?- child(X, john). → Mary, Tom.
Функциональное программирование: основные блоки — функции. Чистая функция для одних и тех же входов даёт один и тот же результат и не меняет внешнее состояние. Данные обычно неизменяемы (изменение = новая копия).

Зачем. Надёжность, простое тестирование, удобнее многопоточность (нет гонок за общее изменяемое состояние).

Типизация языков программирования

Типизация — механизм, задающий тип данным / выражениям. Делят по когда проверяют типы, насколько строго, и указываются ли типы явно.

Когда: статическая и динамическая

Статическая — типы определяются / проверяются на этапе компиляции и дальше не «плавают». Динамическая — типы выясняются во время выполнения.

Слайд 39: static = compile time, dynamic = runtime.

Для формы. Верно: при статической типизации проверка на этапе компиляции; при динамической — во время работы. Обратные утверждения — ложь. Примеры: C/Java — скорее статика; Python/JS — динамика.

Насколько строго: сильная и слабая

Сильная типизация строго соблюдает типы и не делает «тихих» неявных преобразований несовместимых типов без явного указания. Слабая — язык сам конвертирует типы, иногда с сюрпризами.
Пример JavaScript (слабая). 4 + '7' → '47' (склейка строк); 4 * '7' → 28; 2 + true → 3. Python обычно строже к таким смешениям.
Ключ к форме (слайд 41). Сильная/слабая отвечают за то, насколько серьёзно выполняется проверка типов. Динамическая/статическая — за то, когда выполняется проверка. Не наоборот.
