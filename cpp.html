Как это ощущается (без жаргона)

Программа на C++ — это машина, которая хранит числа в «коробках» разного размера, умеет сравнивать («если … то …») и повторять одно и то же действие много раз. Четыре твоих задания как раз про эти четыре навыка по очереди:

  1. коробки с числами — какой тип выбрать, как делить, куда класть большую сумму;
  2. выбор — по знаку, чётности или баллу выдать нужную строку;
  3. повтор — прочитать несколько чисел и посчитать сумму / min / max;
  4. кусочки кода — вынести проверки в функции и собрать из них «журнал».

Своими словами. Сначала учимся аккуратно обращаться с числами, потом — принимать решения, потом — крутить цикл, потом — не писать всё в одной куче. Так же выстроен и сам Stepik-курс: от целых чисел к условиям, циклам и функциям.

С Python. Идеи те же: переменные, if, циклы, функции. Разница — в «жёсткости»: в C++ тип коробки пишешь явно, программу обычно компилируешь перед запуском, а / для двух целых ведёт себя не как в Python 3. Ниже по § — короткие сопоставления; не путай «похоже» с «одинаково».

C++-§0 Устройство программы: что за чем и как она бежит

Пока не трогаем «хитрые» типы и условия. Сначала — каркас: из чего состоит файл .cpp, где программа начинается, и по каким правилам компьютер идёт от строки к строке.

1. Два мира: текст и запуск

Ты пишешь текст на языке C++ (файл вроде main.cpp). Компилятор переводит этот текст в программу, которую уже можно запустить. Пока текст не скомпилирован, «машины» ещё нет — есть только рецепт.

Своими словами. Сначала пишем рецепт → потом компилятор его «запекает» → потом запускаем готовое блюдо. Ошибка на этапе компиляции = рецепт нечитаем. Ошибка при запуске = блюдо приготовилось, но ведёт себя не так.

С Python. Обычно пишешь .py и сразу python file.py — интерпретатор читает текст на лету. В C++ типичный путь: написал .cpp → компилятор собрал исполняемый файл → уже его запускаешь. Синтаксическую опечатку в Python часто увидишь только при достижении строки; в C++ компилятор часто ловит её до любого запуска.

2. С чего начинается выполнение

Определение. Точка входа в обычную консольную программу на C++ — функция main. Операционная система запускает программу и передаёт управление в начало main. Когда main заканчивается (часто через return), программа завершается.

Своими словами. Неважно, сколько функций ты напишешь выше или ниже — выполнение для пользователя начинается с main. Остальные функции сами по себе не бегут: их вызывают.

Пример смысла. В задании 4 функции вроде проверки балла лежат в journal.cpp, а «сценарий дня» — в main.cpp: прочитать вход, в цикле звать функции, напечатать отчёт.
С Python. В обычном скрипте выполнение идёт сверху вниз с первой строки файла — отдельной обязательной main нет. Часто пишут def main(): … и внизу if __name__ == "__main__": main(), но это соглашение, а не правило языка. В C++ без main консольная программа «не знает, с чего стартовать».

3. Что обычно стоит в файле сверху вниз

Типичный порядок в учебном файле (сверху вниз по тексту):

  1. Подключения — строки #include <…>. Это «возьми готовые куски стандартной библиотеки» (ввод-вывод, пределы типов и т.д.). Их читает препроцессор до основной компиляции.
  2. Объявления / свои функции (если они в этом же файле) — чтобы к моменту вызова компилятор уже знал имя и типы аргументов.
  3. int main() — тело программы в фигурных скобках { … }.

Не обязательно зубрить все заголовки сразу. Для начала часто встречаются: <iostream> (ввод-вывод), <limits> (границы типов — в §1), иногда свои .h / соседние .cpp в большом задании.

С Python. #include <iostream> ≈ «подключить готовый модуль», как import. Но это не тот же механизм: заголовок подмешивается на этапе препроцессора/компиляции, а не подгружается при каждом запуске скрипта как модуль Python.
Каркас (смысл)
#include …
функции (по желанию)
int main() { … return 0; }

4. Минимальный скелет — чтобы увидеть порядок

Ниже — не задание и не «решение», а учебные скелеты. Переключай вкладки: от самого короткого к «есть переменная» и «есть ввод», плюс вкладка Python — тот же смысл другим языком. 

#include <iostream>

int main() {
    std::cout << "hello\n";
    return 0;
}
Старт → печать → return 0. Смотри порядок строк.
#include <iostream>

int main() {
    int n;          // объявили коробку
    n = 3;          // положили значение
    std::cout << n; // прочитали и напечатали
    return 0;
}
Сначала объявить, потом пользоваться — всё ещё сверху вниз.
#include <iostream>

int main() {
    int n;
    std::cin >> n;   // прочитать число с входа
    std::cout << n;  // потом напечатать
    return 0;
}
cin и cout — тоже обычные команды в очереди.
print("hello")

print(n)
Тот же порядок «сделай → сделай». Нет main, нет ;, тип у n не пишем.

  • int main() — вход.
  • внутри { } — команды сверху вниз.
  • std::cout / std::cin — из стандартной библиотеки (std::).
  • return 0; — «всё ок»; ненулевой код часто значит ошибку (задание 4).

5. Правила, по которым «течёт» выполнение

Пока нет ветвлений и циклов, закон простой:

Определение. Внутри блока { … } операторы выполняются последовательно: сверху вниз, один за другим, пока не встретится конец блока, return или (позже) переход из-за if / цикла.

Своими словами. Компьютер не «читает файл глазами как рассказ». Он стоит на текущей команде, делает её, переходит к следующей. Фигурные скобки — это «заборчик»: всё внутри одного двора.

6. Оператор, выражение, точка с запятой

  • Оператор (statement) — законченная команда: объявить переменную, присвоить, вызвать функцию, return. В C++ большинство операторов заканчивается точкой с запятой ;.
  • Выражение — кусок, у которого есть значение: 2 + 3, a / b, вызов функции, возвращающей число.
  • Блок { … } сам по себе — тоже оператор (составной): внутри него снова идут операторы по порядку.
Пример. int x = 5; — оператор (объявление + начальное значение). x + 1 — выражение. x = x + 1; — снова оператор.
Не-пример. Забыть ; в конце команды — компилятор часто ругается на «следующей» строке, и кажется, что ошибка «не там». Смотри на предыдущую строку.
С Python. В конце строки ; обычно не нужна (можно, но не принято). Блоки задаёт отступ, а не { }. В C++ отступ — для человека; для компилятора решают скобки и точки с запятой.

7. Переменные: сначала объявить, потом пользоваться

Определение. Переменная — именованная «коробка» в памяти. У неё есть тип и имя. Пока переменная не объявлена в текущей области видимости, обращаться к ней нельзя.

Своими словами. Сначала говоришь языку: «заведи коробку int n», потом кладёшь туда значение и читаешь. Область видимости — обычно от объявления до конца ближайших { }.

Развёрнутый пример с объявлением — вкладка «Переменная» в блоке выше (п. 4).

С Python. Пишешь n = 3 — и коробка появляется: тип выводится из значения, потом можно положить строку в то же имя. В C++ тип фиксируешь при объявлении: int n; потом нельзя сделать n = "hi". Это не «хуже», а другая дисциплина: компилятор раньше ловит путаницу типов.

8. Ввод и вывод — тоже команды по очереди

std::cin >> n; — прочитать в n. std::cout << n; — напечатать. Смотри вкладку «Ввод» в п. 4: они стоят в очереди как любые другие операторы.

Пробелы и переводы строк при чтении чисел cin обычно пропускает сам — об этом ещё раз в §3.

С Python. print(…) ≈ cout; int(input()) ≈ «прочитать строку и сделать int». cin >> n сам понимает, что нужно число, и перескакивает пробелы между числами — удобнее, чем вручную split(), когда на входе поток чисел.

C++-§1 Типы: коробки, деление, большие суммы

Этот параграф нужен для tasks/01_types/types.cpp и ещё всплывёт, когда будешь копить суммы в заданиях 3 и 4. Идём по шагам: сначала «что за коробка», потом «как делят», потом «что бывает, если не влезло».

Шаг 1. Две коробки для целых

В жизни мы пишем «5» и не думаем, сколько байт это занимает. В C++ у целого числа есть тип: от него зависят и диапазон, и то, как сработают операции.

Определение. int — обычное целое со знаком (на типичной машине — 32 бита); long long — целое «пошире» (часто 64 бита). Точные границы int язык даёт через заголовок <limits>: std::numeric_limits<int>::min() и ::max().

Своими словами. int — повседневная коробка: счётчики, баллы, маленькие числа. Если заранее видно, что сумма может перевалить за пару миллиардов — бери коробку побольше (long long).

Пример. $2\,000\,000\,000 + 2\,000\,000\,000 = 4\cdot 10^9$. В типичный int (макс примерно $2{,}147\cdot 10^9$) это уже не лезет. В long long — лезет спокойно.
С Python. Обычный int в Python 3 почти «без потолка»: сумма двух миллиардов просто даст большое целое. В C++ размер коробки фиксирован: «не влезло» — это реальная ловушка, а не редкость. Отсюда и отдельный тип long long, и проверка через numeric_limits.

Шаг 2. Деление «как у целых»

В калькуляторе $5 / 2 = 2{,}5$. В программе, если оба числа целые, язык делает иначе — и это частый сюрприз в начале.

Определение. Если оба операнда целые, оператор / даёт целое частное: дробная часть отбрасывается. В современном C++ округление идёт к нулю.

Своими словами. 5 / 2 — это 2, не 2.5. Для отрицательных то же правило «к нулю»: -5 / 2 даёт -2 (не «вниз до −3», как иногда ждут из школы). 

int a = 7, b = 3;
int q = a / b;   // 2, не 2.333…
Оба операнда int → частное целое.
int q1 = (-5) / 2;   // -2  (к нулю)
int q2 = (-7) / 3;   // -2
Не «вниз до −3», а к нулю.
5 / 2      # 2.5  — в Python 3 обычный / всегда «дробный»
5 // 2     # 2    — целое деление (floor)
(-5) // 2  # -3   — вниз, не к нулю!
В C++ int/int ≈ идея //, но знак у отрицательных другой: C++ к нулю, Python — вниз.
С Python — главное отличие. В Python 3: / даёт float, целое — через //. В C++: / для двух int уже целое; дробь — только если есть double. И ещё: (-5) // 2 в Python это -3, а (-5) / 2 в C++ — -2. Не переноси привычку «как в калькуляторе Python» один в один.
Деление int
оба операнда int → частное int (к нулю)  -5 / 2 == -2

Шаг 3. Когда нужен именно 2.5

Иногда дробный ответ — как раз то, что хочется (среднее, доля, «половина»). Тогда целочисленного деления мало: нужно, чтобы хотя бы одно число считалось действительным.

Определение. Если хотя бы один операнд — double (или его явно привели к double), деление выполняется уже в действительных числах.

Своими словами. Нельзя сначала поделить два int и потом «надеть» дробный тип на результат: дробная часть уже выброшена. Сначала расширь тип, потом дели. 

int a = 5, b = 2;
double x = static_cast<double>(a) / b;  // 2.5
// или: double x = a * 1.0 / b;
Сначала расширили тип — потом делили. (Идея, не решение задания.)
int a = 5, b = 2;
int r = a / b;          // уже 2
double x = r;           // 2.0 — дробь не вернуть
После целочисленного / информация потеряна.
Приведение до деления
нужен double → сначала cast одного операнда, потом /
С Python. float(a) / b или просто a / b (если нужен float) — близко к идее «сделай операнд действительным до деления». В C++ привычный Python-ный / сам дробь не даст, пока оба операнда целые.

Шаг 4. Сложение: расширять до, а не после

Вернёмся к двум миллиардам. Даже если результат ты хочешь положить в большую коробку, опасность в том, в каком типе происходит само сложение.

Определение. Если сложить два int как int, а сумма не влезает — получается переполнение (для знакового целого это плохая ситуация). Запись испорченного значения в long long потом его не «вылечит».

Своими словами. Сначала расширь слагаемые, потом складывай — как переложить яблоки в большой пакет до того, как маленький пакет лопнет. 

int a = 2000000000, b = 2000000000;
long long s = static_cast<long long>(a) + b;  // ок
Расширили до сложения. (Идея типа, не готовая функция задания.)
int a = 2000000000, b = 2000000000;
int bad = a + b;              // уже опасно
long long s = bad;            // «лечение» не сработает
Сначала сложили в int — поздно.
Сумма в long long
cast → сложение  не наоборот
С Python. Сложил два больших int — Python сам расширил число; отдельно «cast до +» не думаешь. В C++ переполнение знакового int — серьёзная ошибка: сначала расширь тип, потом складывай.

Шаг 5. Вопрос «влезает ли обратно в int?»

Иногда число уже лежит в большой коробке, и нужно понять: можно ли его безопасно считать обычным int.

Да — если оно не меньше numeric_limits<int>::min() и не больше ::max() (обе границы включительно).

Пример. $0$ — влезает. Число чуть больше max() — уже нет.

На этом §1 заканчивается. Если хочется проверить себя — тест C++-§1. Дальше мягко переходим к «решениям машины»: условиям.

C++-§2 Ветвления: выбор одной из дорог

Числа мы уже умеем хранить и делить. Следующий навык — выбрать, что делать дальше: отрицательное / ноль / положительное, чёт / нечет, какая метка у балла. Это как раз задание 2 (labels.cpp); те же if-ы пригодятся в задании 4.

if / else if / else

Определение. Ветвление выбирает одну из веток по условию. Цепочка if → else if → … → else проверяется сверху вниз: сработала первая подходящая — остальные не смотрят.

Своими словами. Порядок границ критичен: сначала «вне диапазона», потом узкие интервалы, иначе правильный балл уедет не в ту строку.

Границы включительны там, где сказано: 59 и 60 — разные метки; 89 и 90 — тоже. Ниже — только скелет порядка (не готовый GradeLabel). 

if (/* вне 0..100 */) {
    // invalid
} else if (/* 0..59 */) {
    // fail
} else if (/* 60..74 */) {
    // pass
} else if (/* 75..89 */) {
    // good
} else {
    // 90..100 → excellent
}
Сверху вниз: первая подходящая ветка — и выход из цепочки.
if (x < 0) {
    // negative
} else if (x == 0) {
    // zero
} else {
    // positive
}
Ноль — отдельная ветка, не «положительный».
С Python. Цепочка if / elif / else — почти тот же смысл, что if / else if / else. Отступы вместо { }; условия без обязательных скобок вокруг, но в C++ скобки у условия обязательны: if (x < 0), не if x < 0.

Знак числа

Три случая: строго меньше нуля / ровно ноль / строго больше нуля. Ноль — отдельная метка, не «положительный».

Чётность и оператор %

Определение. a % b — остаток от деления. В C++ знак остатка согласован с делением «к нулю»: для отрицательного делимого остаток может быть отрицательным.

Своими словами. Надёжный тест чётности: «остаток при делении на 2 равен нулю». Сравнивать остаток с 1 ломается на отрицательных: у -3 остаток -1, не 1.

// чётное, в том числе 0 и -4:
if (value % 2 == 0) { /* even */ }
else { /* odd */ }
-4 % 2 == 0. Ноль тоже чётный.
// опасно как единственный тест «нечёт»:
if (value % 2 == 1) { /* … */ }
// у -3 остаток -1, не 1
На отрицательных остаток может быть отрицательным.
(-3) % 2   # в Python → 1  (остаток ≥ 0 при делителе > 0)
# в C++: (-3) % 2 → -1
Тест % 2 == 0 для чётности безопасен в обоих. А «остаток == 1» в C++ на отрицательных ломается.
С Python. Остаток согласован с // (вниз): у отрицательных часто получается неотрицательный остаток. В C++ остаток согласован с делением к нулю — может быть отрицательным. Практическое правило для чётности одно и то же: сравнивай с нулём, не с единицей.
Чётность
чётное ⇔ (value % 2 == 0)  ноль — чётный

C++-§3 Циклы: повторить одно и то же

Условия выбирают одну дорогу. Цикл — когда дорогу нужно пройти несколько раз: прочитать $n$ чисел и по дороге считать сумму, минимум, максимум… Это задание 3; тот же приём — в журнале баллов (задание 4).

Перед деталями — картинка целиком: сначала узнаём, сколько чисел будет, потом столько раз читаем по одному и обновляем «сводку».

Схема «сначала n, потом n чисел»

Определение. Типичный ввод: одно целое $n$ — сколько дальше прочитать чисел; затем ровно $n$ значений. При $n = 0$ цикл по числам не выполняется.

Своими словами. Счётчик итераций и «сколько уже прочитали» — разные роли. Пустой набор — отдельный случай для минимума/максимума.

for и while

Оба подходят. for (int i = 0; i < n; ++i) — когда число шагов известно заранее. Внутри тела: прочитать очередное число, обновить сумму / min / max / счётчик.

С Python. for i in range(n): ≈ «сделай тело n раз» — по смыслу близко к for (int i = 0; i < n; ++i). while в обоих языках — «пока условие истинно». В C++ заголовок for явно пишет инициализацию, проверку и шаг через ; внутри скобок.

Пробелы и std::cin

Определение. Оператор >> для чисел пропускает пробелы, табы и переводы строк одинаково.

Своими словами. Числа в одной строке или каждое с новой — для cin без разницы.

С Python. Часто читают строку и делают map(int, input().split()). cin >> x сам «прыгает» по пробелам между числами — удобно, когда формат «поток чисел», а не «ровно одна строка на всё».

Сумма, min, max, счётчик

  • Сумма больших целых — копи в long long (см. §1).
  • Минимум / максимум: пока ни одного числа не было — нет значения (в задании 3 печатают none, не «ноль по умолчанию»).
  • Строго положительные: условие $x > 0$ (ноль и отрицательные не входят).

Смысл на числах $-2,\;0,\;4,\;-8,\;4$: сумма $-2$, min $-8$, max $4$, строго положительных — два. Ниже — только каркас цикла (не готовое решение задания 3). 

int n;
std::cin >> n;
long long sum = 0;
// … флаг / подготовка min-max …
for (int i = 0; i < n; ++i) {
    int x;
    std::cin >> x;

Сначала n, потом ровно n чисел. Тело — твоё.
// если n == 0, цикл не войдёт ни разу:
// sum остаётся 0
// min/max в задании — "none", не 0
Не инициализируй min/max нулём «на всякий случай».
n = int(input())
total = 0
for _ in range(n):
    x = int(input())  # или читать из потока иначе
    # обновить sum / min / max
Схема та же: сначала n, потом n шагов. В C++ сумма больших целых — сразу думай про long long.

C++-§4 Функции: собрать программу из кусочков

В заданиях 1–3 почти всё живёт «в одном месте». Задание 4 специально учит другому стилю: сначала маленькие функции («валиден ли балл?», «новый минимум?», «какой вердикт?»), потом main только читает вход и склеивает кусочки.

Читай этот параграф спокойно: сначала зачем функции, потом флаг «ещё не было значения», потом порядок вердикта — он капризный к последовательности проверок.

Зачем функции

Определение. Функция — именованный кусок кода с аргументами и возвращаемым значением. Её можно тестировать отдельно от ввода/вывода всей программы.

Своими словами. В задании 4 сначала «кирпичики» (IsValidScore, NextMin, …), потом сборка в main. Так автотесты бьют по функциям до полного прогона.

С Python. def f(x): … ≈ функция с аргументом. В C++ тип пишешь и у результата, и у аргументов: bool IsValidScore(int score) — «вернёт bool, примет int». В Python аннотации (def f(x: int) -> bool) необязательны и по умолчанию не проверяются; в C++ несовпадение типов часто ловит уже компилятор.

Булев флаг «уже было значение»

Для минимума/максимума часто держат флаг has_score (или аналог): пока false — «старого» экстремума нет, первым баллом и становится ответ. Важно вызвать обновление min/max до того, как выставишь флаг в true на первом элементе (иначе логика «ещё нет» не сработает). 

bool has = false;
int cur_min = 0;  // значение до первого балла не считается «настоящим»

// внутри цикла, для очередного score:
// cur_min = NextMin(has, cur_min, score);  // пока !has — вернёт score
// … то же для max …
// has = true;   // уже после обновления min/max
Смысл порядка: сначала NextMin/NextMax, потом has = true.
// в journal.cpp — кирпичики (их тестируют отдельно)
// bool IsValidScore(int score);
// …

// в main — сценарий:
// if (!IsValidScore(score)) { … ошибка … }
Функции сами не бегут: их вызывает main (или тест).

# cur_min = next_min(has, cur_min, score)

Среднее как double

Среднее = сумма / количество. Деление должно быть дробным (см. §1): сумма $2$ и количество $3$ дают $\approx 0{,}666\ldots$, не $0$. Печать с двумя знаками — уже в каркасе main (фиксированный формат).

С Python. sum / count в Python 3 уже даст float. В C++ при двух целых снова целое частное — нужен double (или умножение на 1.0) до деления.

Порядок проверок вердикта

Строго сверху вниз (как в условии задания 4):

  1. count == 0 → empty
  2. passed != count → debt (есть балл < 60)
  3. min_score >= 90 → excellent
  4. иначе → ok

if (passed != count) return "debt";
if (min_score >= 90) return "excellent";
return "ok";

  • $n < 0$ → одна строка invalid count, вернуть $1$, отчёт не печатать.
  • балл вне $0..100$ → invalid score, вернуть $1$, отчёт не печатать.

C++-§5 Структуры: несколько полей в одной коробке

До сих пор у нас была одна переменная — одно значение: int n, long long sum. Но студент — это не одно число. У него четыре «кусочка» данных, и они всегда ходят вместе. Параграф о том, как сказать языку: «вот это — одна вещь из нескольких частей».

1. Проблема: переменные-близнецы

Первый вариант — завести по переменной на каждое поле каждого студента: 

std::string name = "Ivan";
std::string group = "B81";
int exam = 5;
int test = 4;
std::string name2 = "Ivan";
std::string group2 = "B81";
int exam2 = 5;
int test2 = 4;
std::string name3 = "Ivan";
// … и так для каждого студента
3 студента — 12 переменных; 30 студентов — 120. Опечатка exam2 вместо exam3 — и данные перепутаны.
std::vector<std::string> names;
std::vector<std::string> groups;
// … и ещё два вектора для оценок
// студент №i = names[i], groups[i], …
Связь «одного студента» держится только на одинаковом индексе — хрупко.

Своими словами. Оба варианта плохи одним и тем же: «студент» существует только у тебя в голове. Язык видит отдельные строки и числа и не знает, что name2 и exam2 — про одного человека.

2. Что такое структура

Определение. struct — пользовательский тип, составленный из нескольких именованных полей (членов) разных типов. После объявления структуры её имя можно использовать как обычный тип: заводить переменные, класть в векторы, передавать в функции.

Своими словами. Мы рисуем бланк зачётки: «тут имя, тут группа, тут две оценки». Сам бланк — это тип Student. Каждый заполненный бланк — переменная этого типа. 

struct Student {
    std::string name;
    std::string group;
    int exam;
    int test;
};                       // ← точка с запятой обязательна

int main() {
    Student student;             // одна переменная = вся зачётка
    student.name = "Ivan";       // доступ к полю — через точку
    student.group = "B81";
    student.exam = 5;
    student.test = 4;
}
student.name — «поле name у переменной student».
from dataclasses import dataclass

@dataclass
class Student:
    name: str
    group: str
    exam: int
    test: int

student = Student("Ivan", "B81", 5, 4)
print(student.name)
Ближайший аналог — @dataclass. Точка для доступа к полю — та же.
Пример. Тип Student — один; переменных этого типа может быть сколько угодно: Student ivan;, Student anna; — у каждой свои name, exam и т.д. Изменение anna.exam никак не трогает ivan.exam.
Не-пример. Забыть ; после закрывающей } структуры. В отличие от функции, объявление struct — это оператор и закрывается точкой с запятой. Компилятор тогда ругается на следующую строку (обычно на int main), что сбивает с толку.

3. Три способа заполнить структуру сразу

Писать четыре присваивания подряд скучно. Можно короче:

Student student;
student.name = "Ivan";
student.group = "B81";
student.exam = 5;
student.test = 4;
Длинно, но понятно.
Student student{"Ivan", "B81", 5, 4};
std::cout << student.name << "\n";   // Ivan
Значения раскладываются по полям в порядке объявления: name, group, exam, test.
Student student{
    .name = "Ivan",
    .group = "B81",
    .exam = 5,
    .test = 4
};
«Назначенные инициализаторы» (designated initializers): видно, что куда кладём.

Своими словами. Вариант «по порядку» короче, но легко перепутать 5, 4 местами — компилятор не заметит, ведь оба поля int. Вариант с .exam = 5 подписывает каждое значение.

Не-пример. Назначенные инициализаторы требуют того же порядка, что в объявлении: {.exam = 5, .name = "Ivan"} — ошибка (name объявлено раньше exam). Пропускать поля можно, переставлять — нет. И они работают, только пока у структуры нет своих конструкторов (см. §6, п. 5).

4. Присваивание структуры = копия

Определение. Student copy = student; создаёт новую переменную и копирует в неё каждое поле. После этого copy и student — две независимые зачётки. 
Student student{.name = "Ivan", .group = "B81", .exam = 4, .test = 5};
Student copy = student;
copy.name = "Copy";
print(student);   // Ivan B81 4 5   ← оригинал не изменился
print(copy);      // Copy B81 4 5

student = Student("Ivan", "B81", 4, 5)
copy = student           # НЕ копия: второе имя того же объекта
copy.name = "Copy"
print(student.name)      # Copy  ← оригинал тоже изменился!

import copy as cp
real = cp.copy(student)  # настоящая копия — только так
В Python = для объектов копирует только «ярлык».
С Python — важное отличие. В Python b = a для объекта даёт то же самое значение под вторым именем. В C++ Student b = a; — честная копия всех полей. Если в C++ нужно именно «второе имя того же», для этого есть ссылки (§8).

5. Структура в функции: по значению — тоже копия

Печать удобно вынести в функцию:

void print(Student copy) {
    std::cout << copy.name << " " << copy.group << " "
              << copy.exam << " " << copy.test << "\n";
}

Имя параметра copy выбрано не случайно: при вызове print(student) функция получает копию студента (передача по значению). Что бы функция ни сделала с copy, оригинал в main не меняется.

Пример (проверено). void spoil(Student s) { s.test = 0; } — после spoil(student) у student по-прежнему test == 5: обнулили копию. Как передать «сам объект», а не копию, — §8.
Не-пример. Сначала в print забыли "\n" — и две зачётки слиплись в строку Ivan B81 5 4Ivan B81 5 4ok. cout сам перевод строки не ставит.

6. Много студентов: массив структур и циклы

Тип Student можно класть в массив, как любой другой:

Student group[3] = {
    {"Ivan", "B81", 4, 5},
    {"Anna", "B81", 3, 2},
    {"Sergey", "B81", 4, 5},
};
for (int i = 0; i < 3; i++) {
    print(group[i]);
}
// Ivan B81 4 5
// Anna B81 3 2
// Sergey B81 4 5
Student group[3] — массив ровно из 3 студентов; размер фиксирован при объявлении.
for (Student student : group) {
    print(student);
}
«Для каждого student из group» — индекс не нужен. student здесь — копия очередного элемента.
for (auto student : group) {
    print(student);
}
auto — «компилятор, выведи тип сам» (тут выведет Student).
group = [
    Student("Ivan", "B81", 4, 5),
    Student("Anna", "B81", 3, 2),
]
for student in group:
    print(student)
for … : group в C++ ≈ for … in group в Python.
Определение. for (Тип x : контейнер) { … } — цикл «по элементам» (range-based for): тело выполняется для каждого элемента по очереди, и x — очередной элемент. auto вместо типа просит компилятор вывести тип из инициализации.

Своими словами. Индекс i нужен, только если важно «какой по счёту». Если надо просто «пройти всех» — цикл по элементам короче и не даст ошибиться с границей i < 3.

7. std::vector<Student>: список, который растёт

Определение. std::vector<T> (заголовок <vector>) — массив элементов типа T, размер которого может меняться во время работы. push_back(x) добавляет копию x в конец, v[i] — элемент с номером i (с нуля). 
std::vector<Student> group;                       // пока пустой
group.push_back(Student{"Ivan", "B81", 4, 5});      // теперь 1 элемент
std::cout << group[0].name << "\n";                // Ivan
С Python. std::vector ≈ list, push_back ≈ append, group[0] — то же. Разница: в векторе все элементы одного типа (vector<Student> — только студенты), а Student group[3] из п. 6 — вообще фиксированного размера.
Структура
struct Имя { поля; }; · x.поле · Имя b = a; — копия всех полей

C++-§6 Методы и конструкторы: структура, которая умеет действовать

Пока Student — просто бланк с полями, а всё «умное» (печать, подсчёты) живёт в отдельных функциях. Следующий шаг лекции — положить действия внутрь структуры.

1. Метод — функция внутри структуры

Определение. Метод (функция-член) — функция, объявленная внутри struct/class. Вызывается через точку у конкретного объекта: group[0].SumAvg(). Внутри метода поля этого объекта доступны просто по имени — без student..

Своими словами. Метод знает, «чью» зачётку он считает: ivan.SumAvg() берёт оценки Ивана, anna.SumAvg() — Анны. Поэтому внутри можно писать просто exam, а не ivan.exam.

2. Ловушка из §1 снова: среднее получилось 4, а не 4.5

Первая версия среднего выдаёт неожиданный ответ:

struct Student {
    // … поля …
    double SumAvg() {
        return (exam + test) / 2;   // int / int
    }
};
// exam = 4, test = 5
std::cout << group[0].SumAvg();     // 4
(4 + 5) / 2 — оба операнда int, частное 4. Тип double у результата уже не поможет: дробь выброшена до него.
return ((double)exam + (double)test) / 2;   // 4.5
// или короче:
return (double)(exam + test) / 2;           // 4.5
Сначала сделали double, потом делим.
return static_cast<double>(exam + test) / 2;   // 4.5
(double)x — приведение «в стиле C»; static_cast<double>(x) — то же для чисел, но заметнее в коде (как в §1).

Своими словами. Это ровно правило из §1, шаг 3: «сначала расширь тип, потом дели». То, что функция возвращает double, не делает деление внутри неё дробным.

3. Метод может менять объект

void IncTest(int x) {
    test += x;          // меняет поле ЭТОГО студента
}

group[0].IncTest(2);    // было test = 5
std::cout << group[0].test;   // 7
С Python. Метод ≈ def inc_test(self, x): self.test += x. В C++ нет явного self: поля объекта видны внутри метода сами.

4. Конструктор: как объект рождается

Определение. Конструктор — особый метод, который вызывается автоматически при создании объекта. Его имя совпадает с именем структуры, а типа возвращаемого значения нет вовсе (даже void). 
struct Student {
    std::string name;
    std::string group;
    int exam;
    int test;

    Student(std::string name_, std::string group_, int exam_, int test_) {
        name = name_;
        group = group_;
        exam = exam_;
        test = test_;
    }
};

Student student = Student("Ivan", "B81", 4, 5);
print(student);     // Ivan B81 4 5
Подчёркивание в name_ — чтобы параметр не путался с полем name.
class Student:
    def __init__(self, name, group, exam, test):
        self.name = name
        self.group = group
        self.exam = exam
        self.test = test
Конструктор ≈ __init__. В Python поле от параметра отличает self., в C++ — другое имя параметра.

Своими словами. Конструктор — «процедура выдачи зачётки»: нельзя получить объект, не пройдя через неё. Удобно, если при создании надо что-то проверить или посчитать.

5. Несколько конструкторов (перегрузка) и конструктор по умолчанию

Определение. Конструкторов может быть несколько, если у них разные списки параметров (по количеству или типам) — это перегрузка. При создании объекта компилятор выбирает тот, что подходит к переданным аргументам. Конструктор без параметров — конструктор по умолчанию: он работает при Student x;. 
Student(std::string name_, std::string group_, int exam_, int test_) { … }

Student(std::string name_, std::string group_, int exam_) {
    name = group_;     // ← нарочно перепутано
    group = name_;
    exam = exam_;
    test = 0;
}

Student student  = Student("Ivan", "B81", 4, 5);   // 4 аргумента → первый
Student student2 = Student("Anna", "B81", 4);      // 3 аргумента → второй
// Ivan B81 4 5
// B81 Anna 4 0
Вывод B81 Anna показывает: компилятор проверяет только типы, а не смысл. Перепутать два std::string он не помешает.
Student(std::string name_, std::string group_, int exam_, int test_) { … }
Student(std::string name_, std::string group_, int exam_, int test_) { … }

// error: constructor cannot be redeclared
Два конструктора с одинаковыми параметрами — компилятор не понял бы, какой звать.
struct Student {
    std::string name = "";
    std::string group = "B81";   // значения полей по умолчанию
    int exam = 0;
    int test = 5;

    Student() {}                 // конструктор по умолчанию
    // … остальные конструкторы …
};

Student x;
print(x);     //  B81 0 5   (имя пустое)
= "B81" прямо у поля — значение, если конструктор ничего другого не положил.
Не-пример. Убрали значения у полей, оставили пустой Student() {} — вывод был 0 0. Строки действительно пустые (у std::string свой конструктор), а вот int без значения не обязан быть нулём: там лежит «что было в памяти». Ноль на экране — случайность; на другом компьютере может быть мусор. Поэтому полям-числам лучше всегда давать начальное значение.
Не-пример (проверено). Как только у структуры появился хоть один свой конструктор:
  • Student x; работает, только если написан и Student() — сам он больше не создаётся;
  • способ {.name = "Ivan", …} из §5 перестаёт работать: designated initializers cannot be used with a non-aggregate type.

6. Список инициализации

Конструктор можно записать иначе:

Student(std::string name_, std::string group_, int exam_, int test_)
    : name(name_), group(group_), exam(exam_), test(test_) {}

На скриншоте строка обрезана справа; хвост exam(exam_), test(test_) {} восстановлен по смыслу.

Определение. После : и до тела { } конструктора идёт список инициализации: поле(значение) через запятую. Поля получают значения сразу при создании, а не «сначала пустые, потом присвоили» в теле.

Своими словами. Вариант с телом: «выдали пустой бланк, потом вписали имя». Вариант со списком: «бланк сразу напечатан с именем». Результат для наших полей одинаковый, но второй — привычный стиль C++, а для некоторых полей (константы, ссылки) — единственно возможный.

Конструктор
Имя(параметры) : поле(знач), … { } · без типа возврата · перегрузка — разные параметры

C++-§7 Классы: что можно трогать снаружи, а что нет

Сейчас любой код может написать student.exam = 100; — и в зачётке окажется «сотка» по пятибалльной шкале. Классы и модификаторы доступа нужны, чтобы данные можно было менять только «правильными» путями.

1. private и public

Определение. Внутри struct/class метки public: и private: делят члены на группы. public — доступно отовсюду. private — только из методов (и конструкторов) самого типа. Метка действует на всё ниже неё, до следующей метки. 
struct Student {
    private:
    std::string name;      // только для своих
    public:
    std::string group;     // для всех
    int exam;
    int test;
    // … конструкторы, методы …
};

x.name = "Ivan";            // error: 'name' is a private member of 'Student'
x.group = "B82";            // ок

Ошибка возникает и в print, где читают copy.name: снаружи нельзя даже прочитать private-поле.

Своими словами. private — это «внутренняя кухня» объекта. Методы самого Student туда ходят свободно (IncTest спокойно меняет test), а main и чужие функции — нет.

2. struct и class — одно и то же, кроме умолчания

Определение. class и struct в C++ отличаются только доступом по умолчанию (пока не написана ни одна метка): у struct всё public, у class — всё private.
Пример. Заменим одно слово struct Student на class Student, ничего больше не трогая. Посыпались ошибки на всё: 'name' is a private member, 'group' is a private member… и даже calling a private constructor of class 'Student' с пометкой implicitly declared private — конструктор тоже оказался «внутренней кухней», и создать студента из main стало нельзя.

Поэтому типичный класс выглядит так: сверху открытое «меню», снизу закрытые данные.

class StudentClass {
    public:
        StudentClass() {}
        StudentClass(std::string name_, std::string group_, int exam_, int test_) { … }
        double SumAvg() { return (double)(exam + test) / 2; }
        void IncTest(int x) { test += x; }

    private:
        std::string name;
        std::string group;
        int exam;
        int test;
};
Пример — зачем это. Если test закрыт, поменять его можно только через IncTest. Значит, проверку «оценка от 2 до 5» достаточно написать один раз внутри метода — и обойти её снаружи не получится.

Соглашение: struct берут для «просто набора полей» вроде зачётки из §5, class — когда у объекта есть закрытые данные и правила работы с ними.

3. friend: пустить чужую функцию на кухню

Определение. Объявление friend void print(…); внутри класса разрешает этой (внешней) функции доступ к private-членам класса. Сама функция методом не становится и определяется снаружи. 
class StudentClass {
    // …
};

friend void print(StudentClass copy) {    // ← снаружи класса
    std::cout << copy.name << …;
}
// error: 'friend' used outside of class
Слово friend имеет смысл только внутри класса — так не компилируется.
class StudentClass {
public:
    // …
    friend void print(const StudentClass& s);   // «этой функции можно»
private:
    std::string name;
    // …
};

void print(const StudentClass& s) {             // обычная функция
    std::cout << s.name << "\n";                 // private — но ей можно
}
Исправлено (проверено). const …& в параметре — из §8: без копии и без права менять.

4. Деструктор: как объект умирает

Определение. Деструктор ~Имя() — метод, который вызывается автоматически, когда объект перестаёт существовать (например, закончился блок { }, где он объявлен). Без параметров и без типа возврата; у класса он ровно один. 
class Student {
public:
    Student(std::string name_) : name(name_) {}
    ~Student() { std::cout << "deleted " << name << "\n"; }
private:
    std::string name;
};

int main() {
    Student a("Ivan");
    {
        Student b("Anna");
    }                         // ← b умирает здесь: deleted Anna
    std::cout << "end\n";
}                             // ← a умирает здесь: deleted Ivan
// вывод:
// deleted Anna
// end
// deleted Ivan

class StudentClass {
public:
    StudentClass() {}
private:
    // …поля…
    ~StudentClass() { std::cout << "deleted"; }   // ← попал под private
};

int main() { StudentClass s; }
// error: '~StudentClass()' is private within this context
Если деструктор стоит после private:, объект нельзя «похоронить» из main — и нельзя создать. Деструктор пишут в public.

Своими словами. Конструктор — «выдали зачётку», деструктор — «сдали в архив». В C++ момент смерти объекта на стеке точно известен: закрывающая } его блока.

5. Зачем деструктор: убрать за собой

Печать «deleted» — учебная. Настоящая работа деструктора видна в последнем кусочке класса: 

private:
    int* x = nullptr;

~StudentClass() {
    delete x;
    std::cout << "deleted";
}
  • int* x — поле-указатель: хранит не число, а адрес, где число лежит.
  • nullptr — «никуда не указывает».
  • delete x — вернуть системе память, которую когда-то взяли через new. Для nullptr delete ничего не делает — это безопасно.

Идея: если объект сам что-то занял (память, файл), деструктор — то место, где он это отдаёт, чтобы никто не забыл. Что такое указатели и new по-настоящему — следующая тема, здесь только самое необходимое.

С Python. Настоящего private в Python нет: _name — только договорённость «не трогай», доступ всё равно открыт. В C++ private проверяет компилятор — нарушение не скомпилируется. Деструктор ≈ __del__, но в Python момент его вызова не гарантирован (решает сборщик мусора), а в C++ для обычной переменной — ровно на }.
Доступ
struct: всё public по умолчанию · class: всё private по умолчанию · friend — только внутри класса
⚡ Быстрый тест: в чат тест C++-§7 — class/struct, private, friend, деструктор

C++-§8 Ссылки: второе имя той же переменной

В §5 мы видели, что Student b = a; и передача в функцию создают копии. Часто это не то, что нужно: хочется, чтобы функция изменила сам объект, или не тратить время на копирование. Для этого — ссылки.

1. Что такое ссылка

Определение. int& alias = x; объявляет ссылку alias на переменную x: это не новая коробка, а второе имя той же самой. Любое чтение или запись через alias — это чтение или запись x. Ссылку обязательно связать с переменной сразу при объявлении.

Своими словами. Как прозвище: «Ваня» и «Иван Петров» — один человек. Дали Ване пятёрку — у Ивана Петрова тоже пятёрка, потому что это он и есть. 

int x = 5;
int& alias = x;
std::cout << x << " " << alias << "\n";   // 5 5
alias = 4;                                  // пишем через второе имя
std::cout << x << " " << alias << "\n";   // 4 4  ← x тоже 4

2. Ссылку нельзя «перевесить»

Каверзный момент:

int other = 10;
alias = other;       // НЕ «теперь alias — имя other»!
std::cout << x << " " << alias << "\n";   // 10 10
Определение. После объявления ссылка навсегда привязана к своей переменной. alias = other; — это обычное присваивание: значение other записывается в x.
Пример (проверено). Если после этого написать other = 99;, то x и alias останутся 10: связи с other нет, было только разовое копирование числа.
Не-пример. int& r; без = что-то — ошибка компиляции: ссылка «ни на что» не бывает.

3. const-ссылка: смотреть, но не трогать

int x = 5;
const int& alias = x;
x += 5;
std::cout << alias << "\n";   // 10 — видит изменения x
// alias = 3;                   // ошибка: через const-ссылку менять нельзя

Своими словами. Это «окошко только для чтения» в ту же коробку: что положили в x, то и видно, но через само окошко ничего не положишь.

4. Ссылка в параметре функции

Определение. Если параметр функции объявлен как int& x, функция получает не копию аргумента, а ссылку на него (передача по ссылке): изменения x внутри видны снаружи. 
void add(int& x, int y) {
    x += y;
    std::cout << x << "\n";
}

int x = 0;
add(x, 5);                 // 5
std::cout << x << "\n";    // 5   ← x в main изменился
Один символ & решает, меняется ли переменная вызывающего.
void add(int x, int y) {   // без &
    x += y;
    std::cout << x << "\n";
}

int x = 0;
add(x, 5);                 // 5
std::cout << x << "\n";    // 0   ← меняли копию
Для сравнения.
def add(x, y):
    x += y        # для int — новый объект, снаружи не видно

x = 0
add(x, 5)
print(x)          # 0
В Python число из функции так не изменить. В C++ — можно, если явно написать &.

5. auto& в цикле по элементам

for (auto student : group)  student.IncTest(10);   // меняем копии → в group ничего не изменилось
for (auto& student : group) student.IncTest(10);   // меняем сами элементы group
Пример (проверено). У Анны test = 2. После первого цикла у group[0] всё ещё 2, после второго — 12. Без & переменная цикла — копия элемента (как в §5, п. 6); с & — второе имя самого элемента.

6. Как это собирает всю лекцию

Вернёмся к void print(Student copy) из §5: каждый вызов копирует строки имени и группы — зря, мы ведь только печатаем. Три варианта параметра:

ПараметрКопия?Может изменить оригинал?Когда
Student sданетмаленькие типы (int), или нужна своя копия
Student& sнетдафункция должна изменить объект
const Student& sнетнеттолько читать большой объект — как print
С Python. В Python имя всегда «ярлык» на объект, и списки/объекты функция может менять, а числа и строки — нет. В C++ правило одно для всех типов и видно в сигнатуре: без & — копия, с & — оригинал, с const & — оригинал только для чтения.
Ссылки
T& r = x; — второе имя x (навсегда) · const T& — без копии, только чтение · r = y; — копия значения, не перепривязка
