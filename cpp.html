Как это ощущается (без жаргона)

Программа на C++ — это машина, которая хранит числа в «коробках» разного размера, умеет сравнивать («если … то …») и повторять одно и то же действие много раз. Четыре твоих задания как раз про эти четыре навыка по очереди:

  1. коробки с числами — какой тип выбрать, как делить, куда класть большую сумму;
  2. выбор — по знаку, чётности или баллу выдать нужную строку;
  3. повтор — прочитать несколько чисел и посчитать сумму / min / max;
  4. кусочки кода — вынести проверки в функции и собрать из них «журнал».

Своими словами. Сначала учимся аккуратно обращаться с числами, потом — принимать решения, потом — крутить цикл, потом — не писать всё в одной куче. Так же выстроен и сам Stepik-курс: от целых чисел к условиям, циклам и функциям.

С Python. Идеи те же: переменные, if, циклы, функции. Разница — в «жёсткости»: в C++ тип коробки пишешь явно, программу обычно компилируешь перед запуском, а / для двух целых ведёт себя не как в Python 3. Ниже по § — короткие сопоставления; не путай «похоже» с «одинаково».

C++-§0 Устройство программы: что за чем и как она бежит

Пока не трогаем «хитрые» типы и условия. Сначала — каркас: из чего состоит файл .cpp, где программа начинается, и по каким правилам компьютер идёт от строки к строке.

1. Два мира: текст и запуск

Ты пишешь текст на языке C++ (файл вроде main.cpp). Компилятор переводит этот текст в программу, которую уже можно запустить. Пока текст не скомпилирован, «машины» ещё нет — есть только рецепт.

Своими словами. Сначала пишем рецепт → потом компилятор его «запекает» → потом запускаем готовое блюдо. Ошибка на этапе компиляции = рецепт нечитаем. Ошибка при запуске = блюдо приготовилось, но ведёт себя не так.

С Python. Обычно пишешь .py и сразу python file.py — интерпретатор читает текст на лету. В C++ типичный путь: написал .cpp → компилятор собрал исполняемый файл → уже его запускаешь. Синтаксическую опечатку в Python часто увидишь только при достижении строки; в C++ компилятор часто ловит её до любого запуска.

2. С чего начинается выполнение

Определение. Точка входа в обычную консольную программу на C++ — функция main. Операционная система запускает программу и передаёт управление в начало main. Когда main заканчивается (часто через return), программа завершается.

Своими словами. Неважно, сколько функций ты напишешь выше или ниже — выполнение для пользователя начинается с main. Остальные функции сами по себе не бегут: их вызывают.

Пример смысла. В задании 4 функции вроде проверки балла лежат в journal.cpp, а «сценарий дня» — в main.cpp: прочитать вход, в цикле звать функции, напечатать отчёт.
С Python. В обычном скрипте выполнение идёт сверху вниз с первой строки файла — отдельной обязательной main нет. Часто пишут def main(): … и внизу if __name__ == "__main__": main(), но это соглашение, а не правило языка. В C++ без main консольная программа «не знает, с чего стартовать».

3. Что обычно стоит в файле сверху вниз

Типичный порядок в учебном файле (сверху вниз по тексту):

  1. Подключения — строки #include <…>. Это «возьми готовые куски стандартной библиотеки» (ввод-вывод, пределы типов и т.д.). Их читает препроцессор до основной компиляции.
  2. Объявления / свои функции (если они в этом же файле) — чтобы к моменту вызова компилятор уже знал имя и типы аргументов.
  3. int main() — тело программы в фигурных скобках { … }.

Не обязательно зубрить все заголовки сразу. Для начала часто встречаются: <iostream> (ввод-вывод), <limits> (границы типов — в §1), иногда свои .h / соседние .cpp в большом задании.

С Python. #include <iostream> ≈ «подключить готовый модуль», как import. Но это не тот же механизм: заголовок подмешивается на этапе препроцессора/компиляции, а не подгружается при каждом запуске скрипта как модуль Python.
Каркас (смысл)
#include …
функции (по желанию)
int main() { … return 0; }

4. Минимальный скелет — чтобы увидеть порядок

Ниже — не задание и не «решение», а учебные скелеты. Переключай вкладки: от самого короткого к «есть переменная» и «есть ввод», плюс вкладка Python — тот же смысл другим языком. 

#include <iostream>

int main() {
    std::cout << "hello\n";
    return 0;
}
Старт → печать → return 0. Смотри порядок строк.
#include <iostream>

int main() {
    int n;          // объявили коробку
    n = 3;          // положили значение
    std::cout << n; // прочитали и напечатали
    return 0;
}
Сначала объявить, потом пользоваться — всё ещё сверху вниз.
#include <iostream>

int main() {
    int n;
    std::cin >> n;   // прочитать число с входа
    std::cout << n;  // потом напечатать
    return 0;
}
cin и cout — тоже обычные команды в очереди.
print("hello")

n = 3
print(n)

n = int(input())   # прочитать число
print(n)
Тот же порядок «сделай → сделай». Нет main, нет ;, тип у n не пишем.
  • #include <iostream> — подключили печать/чтение.
  • int main() — вход.
  • внутри { } — команды сверху вниз.
  • std::cout / std::cin — из стандартной библиотеки (std::).
  • return 0; — «всё ок»; ненулевой код часто значит ошибку (задание 4).

5. Правила, по которым «течёт» выполнение

Пока нет ветвлений и циклов, закон простой:

Определение. Внутри блока { … } операторы выполняются последовательно: сверху вниз, один за другим, пока не встретится конец блока, return или (позже) переход из-за if / цикла.

Своими словами. Компьютер не «читает файл глазами как рассказ». Он стоит на текущей команде, делает её, переходит к следующей. Фигурные скобки — это «заборчик»: всё внутри одного двора.

6. Оператор, выражение, точка с запятой

  • Оператор (statement) — законченная команда: объявить переменную, присвоить, вызвать функцию, return. В C++ большинство операторов заканчивается точкой с запятой ;.
  • Выражение — кусок, у которого есть значение: 2 + 3, a / b, вызов функции, возвращающей число.
  • Блок { … } сам по себе — тоже оператор (составной): внутри него снова идут операторы по порядку.
Пример. int x = 5; — оператор (объявление + начальное значение). x + 1 — выражение. x = x + 1; — снова оператор.
Не-пример. Забыть ; в конце команды — компилятор часто ругается на «следующей» строке, и кажется, что ошибка «не там». Смотри на предыдущую строку.
С Python. В конце строки ; обычно не нужна (можно, но не принято). Блоки задаёт отступ, а не { }. В C++ отступ — для человека; для компилятора решают скобки и точки с запятой.

7. Переменные: сначала объявить, потом пользоваться

Определение. Переменная — именованная «коробка» в памяти. У неё есть тип и имя. Пока переменная не объявлена в текущей области видимости, обращаться к ней нельзя.

Своими словами. Сначала говоришь языку: «заведи коробку int n», потом кладёшь туда значение и читаешь. Область видимости — обычно от объявления до конца ближайших { }.

Развёрнутый пример с объявлением — вкладка «Переменная» в блоке выше (п. 4).

С Python. Пишешь n = 3 — и коробка появляется: тип выводится из значения, потом можно положить строку в то же имя. В C++ тип фиксируешь при объявлении: int n; потом нельзя сделать n = "hi". Это не «хуже», а другая дисциплина: компилятор раньше ловит путаницу типов.

8. Ввод и вывод — тоже команды по очереди

std::cin >> n; — прочитать в n. std::cout << n; — напечатать. Смотри вкладку «Ввод» в п. 4: они стоят в очереди как любые другие операторы.

Пробелы и переводы строк при чтении чисел cin обычно пропускает сам — об этом ещё раз в §3.

С Python. print(…) ≈ cout; int(input()) ≈ «прочитать строку и сделать int». cin >> n сам понимает, что нужно число, и перескакивает пробелы между числами — удобнее, чем вручную split(), когда на входе поток чисел.

10. Комментарии

// — комментарий до конца строки. /* … */ — многострочный. Компилятор их игнорирует: для человека, не для машины.

С Python. # — однострочный комментарий (как //). Многострочных «как /* */» в языке нет: обычно несколько строк с # или строка в тройных кавычках как документация.

C++-§1 Типы: коробки, деление, большие суммы

Этот параграф нужен для tasks/01_types/types.cpp и ещё всплывёт, когда будешь копить суммы в заданиях 3 и 4. Идём по шагам: сначала «что за коробка», потом «как делят», потом «что бывает, если не влезло».

Шаг 1. Две коробки для целых

В жизни мы пишем «5» и не думаем, сколько байт это занимает. В C++ у целого числа есть тип: от него зависят и диапазон, и то, как сработают операции.

Определение. int — обычное целое со знаком (на типичной машине — 32 бита); long long — целое «пошире» (часто 64 бита). Точные границы int язык даёт через заголовок <limits>: std::numeric_limits<int>::min() и ::max().

Своими словами. int — повседневная коробка: счётчики, баллы, маленькие числа. Если заранее видно, что сумма может перевалить за пару миллиардов — бери коробку побольше (long long).

Пример. $2\,000\,000\,000 + 2\,000\,000\,000 = 4\cdot 10^9$. В типичный int (макс примерно $2{,}147\cdot 10^9$) это уже не лезет. В long long — лезет спокойно.
С Python. Обычный int в Python 3 почти «без потолка»: сумма двух миллиардов просто даст большое целое. В C++ размер коробки фиксирован: «не влезло» — это реальная ловушка, а не редкость. Отсюда и отдельный тип long long, и проверка через numeric_limits.
Границы int
#include <limits>
std::numeric_limits<int>::min() · · · ::max()

Шаг 2. Деление «как у целых»

В калькуляторе $5 / 2 = 2{,}5$. В программе, если оба числа целые, язык делает иначе — и это частый сюрприз в начале.

Определение. Если оба операнда целые, оператор / даёт целое частное: дробная часть отбрасывается. В современном C++ округление идёт к нулю.

Своими словами. 5 / 2 — это 2, не 2.5. Для отрицательных то же правило «к нулю»: -5 / 2 даёт -2 (не «вниз до −3», как иногда ждут из школы). 

int a = 7, b = 3;
int q = a / b;   // 2, не 2.333…
Оба операнда int → частное целое.
int q1 = (-5) / 2;   // -2  (к нулю)
int q2 = (-7) / 3;   // -2
Не «вниз до −3», а к нулю.
5 / 2      # 2.5  — в Python 3 обычный / всегда «дробный»
5 // 2     # 2    — целое деление (floor)
(-5) // 2  # -3   — вниз, не к нулю!
В C++ int/int ≈ идея //, но знак у отрицательных другой: C++ к нулю, Python — вниз.
С Python — главное отличие. В Python 3: / даёт float, целое — через //. В C++: / для двух int уже целое; дробь — только если есть double. И ещё: (-5) // 2 в Python это -3, а (-5) / 2 в C++ — -2. Не переноси привычку «как в калькуляторе Python» один в один.
Деление int
оба операнда int → частное int (к нулю)  -5 / 2 == -2

Шаг 3. Когда нужен именно 2.5

Иногда дробный ответ — как раз то, что хочется (среднее, доля, «половина»). Тогда целочисленного деления мало: нужно, чтобы хотя бы одно число считалось действительным.

Определение. Если хотя бы один операнд — double (или его явно привели к double), деление выполняется уже в действительных числах.

Своими словами. Нельзя сначала поделить два int и потом «надеть» дробный тип на результат: дробная часть уже выброшена. Сначала расширь тип, потом дели. 

int a = 5, b = 2;
double x = static_cast<double>(a) / b;  // 2.5
// или: double x = a * 1.0 / b;
Сначала расширили тип — потом делили. (Идея, не решение задания.)
int a = 5, b = 2;
int r = a / b;          // уже 2
double x = r;           // 2.0 — дробь не вернуть
После целочисленного / информация потеряна.
Приведение до деления
нужен double → сначала cast одного операнда, потом /
С Python. float(a) / b или просто a / b (если нужен float) — близко к идее «сделай операнд действительным до деления». В C++ привычный Python-ный / сам дробь не даст, пока оба операнда целые.

Шаг 4. Сложение: расширять до, а не после

Вернёмся к двум миллиардам. Даже если результат ты хочешь положить в большую коробку, опасность в том, в каком типе происходит само сложение.

Определение. Если сложить два int как int, а сумма не влезает — получается переполнение (для знакового целого это плохая ситуация). Запись испорченного значения в long long потом его не «вылечит».

Своими словами. Сначала расширь слагаемые, потом складывай — как переложить яблоки в большой пакет до того, как маленький пакет лопнет. 

int a = 2000000000, b = 2000000000;
long long s = static_cast<long long>(a) + b;  // ок
Расширили до сложения. (Идея типа, не готовая функция задания.)
int a = 2000000000, b = 2000000000;
int bad = a + b;              // уже опасно
long long s = bad;            // «лечение» не сработает
Сначала сложили в int — поздно.
Сумма в long long
cast → сложение  не наоборот
С Python. Сложил два больших int — Python сам расширил число; отдельно «cast до +» не думаешь. В C++ переполнение знакового int — серьёзная ошибка: сначала расширь тип, потом складывай.

Шаг 5. Вопрос «влезает ли обратно в int?»

Иногда число уже лежит в большой коробке, и нужно понять: можно ли его безопасно считать обычным int.

Да — если оно не меньше numeric_limits<int>::min() и не больше ::max() (обе границы включительно).

Пример. $0$ — влезает. Число чуть больше max() — уже нет.

C++-§2 Ветвления: выбор одной из дорог

Числа мы уже умеем хранить и делить. Следующий навык — выбрать, что делать дальше: отрицательное / ноль / положительное, чёт / нечет, какая метка у балла. Это как раз задание 2 (labels.cpp); те же if-ы пригодятся в задании 4.

if / else if / else

Определение. Ветвление выбирает одну из веток по условию. Цепочка if → else if → … → else проверяется сверху вниз: сработала первая подходящая — остальные не смотрят.

Своими словами. Порядок границ критичен: сначала «вне диапазона», потом узкие интервалы, иначе правильный балл уедет не в ту строку.

Границы включительны там, где сказано: 59 и 60 — разные метки; 89 и 90 — тоже. Ниже — только скелет порядка (не готовый GradeLabel). 

if (/* вне 0..100 */) {
    // invalid
} else if (/* 0..59 */) {
    // fail
} else if (/* 60..74 */) {
    // pass
} else if (/* 75..89 */) {
    // good
} else {
    // 90..100 → excellent
}
Сверху вниз: первая подходящая ветка — и выход из цепочки.
if (x < 0) {
    // negative
} else if (x == 0) {
    // zero
} else {
    // positive
}
Ноль — отдельная ветка, не «положительный».
С Python. Цепочка if / elif / else — почти тот же смысл, что if / else if / else. Отступы вместо { }; условия без обязательных скобок вокруг, но в C++ скобки у условия обязательны: if (x < 0), не if x < 0.

Знак числа

Три случая: строго меньше нуля / ровно ноль / строго больше нуля. Ноль — отдельная метка, не «положительный».

Чётность и оператор %

Определение. a % b — остаток от деления. В C++ знак остатка согласован с делением «к нулю»: для отрицательного делимого остаток может быть отрицательным.

Своими словами. Надёжный тест чётности: «остаток при делении на 2 равен нулю». Сравнивать остаток с 1 ломается на отрицательных: у -3 остаток -1, не 1.

// чётное, в том числе 0 и -4:
if (value % 2 == 0) { /* even */ }
else { /* odd */ }
-4 % 2 == 0. Ноль тоже чётный.
// опасно как единственный тест «нечёт»:
if (value % 2 == 1) { /* … */ }
// у -3 остаток -1, не 1
На отрицательных остаток может быть отрицательным.
(-3) % 2   # в Python → 1  (остаток ≥ 0 при делителе > 0)
# в C++: (-3) % 2 → -1
Тест % 2 == 0 для чётности безопасен в обоих. А «остаток == 1» в C++ на отрицательных ломается.
С Python. Остаток согласован с // (вниз): у отрицательных часто получается неотрицательный остаток. В C++ остаток согласован с делением к нулю — может быть отрицательным. Практическое правило для чётности одно и то же: сравнивай с нулём, не с единицей.
Чётность
чётное ⇔ (value % 2 == 0)  ноль — чётный

C++-§3 Циклы: повторить одно и то же

Условия выбирают одну дорогу. Цикл — когда дорогу нужно пройти несколько раз: прочитать $n$ чисел и по дороге считать сумму, минимум, максимум… Это задание 3; тот же приём — в журнале баллов (задание 4).

Перед деталями — картинка целиком: сначала узнаём, сколько чисел будет, потом столько раз читаем по одному и обновляем «сводку».

Схема «сначала n, потом n чисел»

Определение. Типичный ввод: одно целое $n$ — сколько дальше прочитать чисел; затем ровно $n$ значений. При $n = 0$ цикл по числам не выполняется.

Своими словами. Счётчик итераций и «сколько уже прочитали» — разные роли. Пустой набор — отдельный случай для минимума/максимума.

for и while

Оба подходят. for (int i = 0; i < n; ++i) — когда число шагов известно заранее. Внутри тела: прочитать очередное число, обновить сумму / min / max / счётчик.

С Python. for i in range(n): ≈ «сделай тело n раз» — по смыслу близко к for (int i = 0; i < n; ++i). while в обоих языках — «пока условие истинно». В C++ заголовок for явно пишет инициализацию, проверку и шаг через ; внутри скобок.

Пробелы и std::cin

Определение. Оператор >> для чисел пропускает пробелы, табы и переводы строк одинаково.

Своими словами. Числа в одной строке или каждое с новой — для cin без разницы.

С Python. Часто читают строку и делают map(int, input().split()). cin >> x сам «прыгает» по пробелам между числами — удобно, когда формат «поток чисел», а не «ровно одна строка на всё».

Сумма, min, max, счётчик

  • Сумма больших целых — копи в long long (см. §1).
  • Минимум / максимум: пока ни одного числа не было — нет значения (в задании 3 печатают none, не «ноль по умолчанию»).
  • Строго положительные: условие $x > 0$ (ноль и отрицательные не входят).

Смысл на числах $-2,\;0,\;4,\;-8,\;4$: сумма $-2$, min $-8$, max $4$, строго положительных — два. Ниже — только каркас цикла (не готовое решение задания 3). 

int n;
std::cin >> n;
long long sum = 0;
// … флаг / подготовка min-max …
for (int i = 0; i < n; ++i) {
    int x;
    std::cin >> x;
    // обновить sum / min / max / счётчик
}
Сначала n, потом ровно n чисел. Тело — твоё.
// если n == 0, цикл не войдёт ни разу:
// sum остаётся 0
// min/max в задании — "none", не 0
Не инициализируй min/max нулём «на всякий случай».
n = int(input())
total = 0
for _ in range(n):
    x = int(input())  # или читать из потока иначе
    # обновить sum / min / max
Схема та же: сначала n, потом n шагов. В C++ сумма больших целых — сразу думай про long long.
Пустой набор
n == 0 → min/max = none  сумма всё равно 0  positive = 0

C++-§4 Функции: собрать программу из кусочков

В заданиях 1–3 почти всё живёт «в одном месте». Задание 4 специально учит другому стилю: сначала маленькие функции («валиден ли балл?», «новый минимум?», «какой вердикт?»), потом main только читает вход и склеивает кусочки.

Читай этот параграф спокойно: сначала зачем функции, потом флаг «ещё не было значения», потом порядок вердикта — он капризный к последовательности проверок.

Зачем функции

Определение. Функция — именованный кусок кода с аргументами и возвращаемым значением. Её можно тестировать отдельно от ввода/вывода всей программы.

Своими словами. В задании 4 сначала «кирпичики» (IsValidScore, NextMin, …), потом сборка в main. Так автотесты бьют по функциям до полного прогона.

С Python. def f(x): … ≈ функция с аргументом. В C++ тип пишешь и у результата, и у аргументов: bool IsValidScore(int score) — «вернёт bool, примет int». В Python аннотации (def f(x: int) -> bool) необязательны и по умолчанию не проверяются; в C++ несовпадение типов часто ловит уже компилятор.

Булев флаг «уже было значение»

Для минимума/максимума часто держат флаг has_score (или аналог): пока false — «старого» экстремума нет, первым баллом и становится ответ. Важно вызвать обновление min/max до того, как выставишь флаг в true на первом элементе (иначе логика «ещё нет» не сработает). 

bool has = false;
int cur_min = 0;  // значение до первого балла не считается «настоящим»

// внутри цикла, для очередного score:
// cur_min = NextMin(has, cur_min, score);  // пока !has — вернёт score
// … то же для max …
// has = true;   // уже после обновления min/max
Смысл порядка: сначала NextMin/NextMax, потом has = true.
// в journal.cpp — кирпичики (их тестируют отдельно)
// bool IsValidScore(int score);
// …

// в main — сценарий:
// if (!IsValidScore(score)) { … ошибка … }
Функции сами не бегут: их вызывает main (или тест).
has = False          # bool с большой буквы в литералах
# cur_min = next_min(has, cur_min, score)
# has = True

# вызов: if not is_valid_score(score): …
false/true в C++ — с маленькой; в Python — False/True. Идея флага та же.

Среднее как double

Среднее = сумма / количество. Деление должно быть дробным (см. §1): сумма $2$ и количество $3$ дают $\approx 0{,}666\ldots$, не $0$. Печать с двумя знаками — уже в каркасе main (фиксированный формат).

С Python. sum / count в Python 3 уже даст float. В C++ при двух целых снова целое частное — нужен double (или умножение на 1.0) до деления.

Порядок проверок вердикта

Строго сверху вниз (как в условии задания 4):

  1. count == 0 → empty
  2. passed != count → debt (есть балл < 60)
  3. min_score >= 90 → excellent
  4. иначе → ok
if (count == 0) return "empty";
if (passed != count) return "debt";
if (min_score >= 90) return "excellent";
return "ok";
Строго сверху вниз — как в условии задания 4.
// 90 90 50 → debt (есть балл < 60), не excellent
// пустой журнал → empty, даже «если бы» смотрели на min
Переставить проверки — получить чужой вердикт.
Вердикт (порядок)
empty → debt → excellent → ok

Ошибки ввода и код возврата

  • $n < 0$ → одна строка invalid count, вернуть $1$, отчёт не печатать.
  • балл вне $0..100$ → invalid score, вернуть $1$, отчёт не печатать.
  • Зачёт по одному баллу: $\ge 60$. failed в отчёте = count - passed (уже в каркасе).
